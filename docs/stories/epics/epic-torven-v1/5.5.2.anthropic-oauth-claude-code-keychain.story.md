# Story 5.5.2 — Anthropic OAuth via Claude Code Keychain + token expiry verify (ISSUE-D)

**Story ID:** 5.5.2.anthropic-oauth-claude-code-keychain
**Status:** InReview
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 5.5 — Polish (carry-forwards Wave 5)

---

## Story (User Story)

**As a** usuário do Torven que autentica via **Claude Code** (não Claude CLI standalone),
**I want** o Torven detectar e usar minhas credenciais Anthropic do Keychain `"Claude Code-credentials"` ao invés do path obsoleto `~/.claude/.credentials.json` (que só existe se eu uso o legacy Claude CLI),
**so that** o Settings UI mostre OAuth como "connected" corretamente E o Refresh button consiga fetch real-API Anthropic spend sem precisar instalar Claude CLI standalone separado.

---

## Contexto e Motivação

Story 5.2 implementou OAuth status probe via `FileManager.fileExists(atPath: ~/.claude/.credentials.json)`. Story 1.15+ e Story 4.x fetch usam o mesmo path. Mas:

- **Claude CLI standalone** (`brew install anthropic-ai/claude-cli/claude`): grava em `~/.claude/.credentials.json`
- **Claude Code** (`brew install --cask claude`): grava em macOS Keychain entry chamada `"Claude Code-credentials"`

Lorenzo usa **Claude Code** (confirmado bench 2026-06-07). Probe atual sempre retorna `.notConfigured` mesmo Lorenzo logado.

**Esse bug é maior que apenas status display:**
- AC-1 OAuth probe (Settings UI) — cosmético: false negative no badge
- AC-2 Fetch real API call: o `vendors/anthropic/fetch.rs::fetch_snapshot()` lê `creds_path: &Path` que aponta pro arquivo. Sem arquivo = sem fetch = sem dados Anthropic no chart.
- O bug significa que **toda a estória 1.15 (AI Insights baseline 0.90/1.00) só funcionou em testes mocados ou em máquinas com Claude CLI standalone instalado**, não no setup real do Lorenzo.

**Decisões cravadas:**
- **WAVE5.5-D5:** **Dual-source** — Keychain `"Claude Code-credentials"` é primary, file `~/.claude/.credentials.json` é fallback. Suporta usuários de ambos os fluxos. Decisão de "primary" via `try keychain first; fall back to file` ordering em Rust + Swift.
- **WAVE5.5-D6:** Story inclui spike pra **descobrir schema do Keychain `"Claude Code-credentials"`**. Sem schema sabido, @dev não consegue parse. AC-0 abaixo.
- **WAVE5.5-D7:** **Token expiry verify real** entra junto — atual probe (file-exists) ignora se o token está expirado. Status probe nova deve retornar `.connected` apenas se token estiver válido (não-expirado).
- **WAVE5.5-D8:** Update CLAUDE.md secret-discipline rule (lines 80-87 atual) — Keychain queries devem ser tratadas como leituras de credenciais OAuth com mesmo cuidado de `jq 'keys'` files: NÃO logar conteúdo dos blobs, apenas chaves/metadata.
- **WAVE5.5-D9:** Story NÃO toca em OpenAI Codex CLI path (`~/.codex/auth.json`) — file-based, funcionando, fora de escopo.

### Phase 1 — Rust creds source dual

**AC-1:** `crates/torven-core/src/vendors/anthropic/creds.rs` ganha enum `CredsSource`:
```rust
pub enum CredsSource {
    File(PathBuf),                       // legacy ~/.claude/.credentials.json
    Keychain(String),                    // service name "Claude Code-credentials"
}

pub fn read_from_source(source: &CredsSource) -> Result<ClaudeAiOauth> {
    match source {
        CredsSource::File(p) => read_from(p),
        CredsSource::Keychain(svc) => read_from_keychain(svc),
    }
}

pub fn write_back_to_source(source: &CredsSource, oauth: &ClaudeAiOauth) -> Result<()> { ... }
```

**AC-2:** `read_from_keychain(service)` usa `keyring` crate (já workspace dep da Story 1.13/Wave 5) pra ler Keychain entry, deserializar como JSON, mapear pra `ClaudeAiOauth`.

**AC-3:** `write_back_to_keychain(service, oauth)` simétrico — usado após `oauth::refresh` pra persistir novo access_token + refresh_token + expires_at.

**AC-4:** `fetch_snapshot()` (`fetch.rs:56`) signature muda de `creds_path: &Path` pra `creds_source: &CredsSource`. Callers atualizados.

**AC-5:** Default resolver function `default_anthropic_creds_source()` em `creds.rs`:
```rust
pub fn default_anthropic_creds_source() -> CredsSource {
    // Try Keychain first (Claude Code); fall back to file (legacy Claude CLI)
    if read_from_keychain("Claude Code-credentials").is_ok() {
        CredsSource::Keychain("Claude Code-credentials".into())
    } else {
        CredsSource::File(default_creds_file_path())
    }
}
```

## Dev Notes

### Constraints técnicas

- **`keyring` crate cross-platform:** já workspace dep (Story 1.13 wave 5). Mas macOS Keychain access pode requerer `Security.framework` linkage ou entitlement. Verificar Story 1.13's keychain_blob.rs pra padrões.
- **Schema unknown até AC-0:** essa é a maior incógnita. Provavelmente `{ "claudeAiOauth": { "accessToken": "...", "refreshToken": "...", "expiresAt": ..., ... } }` mirroring file format — mas confirmar antes de codar. Spike é BLOCKING — se NEEDS-ADAPT, scope da story aumenta.
- **`security` CLI vs Keychain API:** `security` é CLI shell tool, mas Rust app vai usar `keyring` crate (que internamente usa Security.framework). Esperar comportamento equivalente; if discrepâncias, troubleshoot via Apple docs.
- **Async FFI:** `ffiAnthropicOauthStatus` é `[Async]` UDL pra não bloquear UI thread durante Keychain query. AR-2 cancel pattern aplica.
- **Token expiry check unit:** `expires_at_ms` em ClaudeAiOauth é ms epoch. `now()` deve usar mesmo unit. Story 1.15+ tem `oauth::needs_refresh` pattern — re-use.

### Implementation log (IDS decisions)

| Decision | REUSE/ADAPT/CREATE | Justification |
|---|---|---|
| Use `security_framework::passwords::{get,set}_generic_password` for Claude Code Keychain reader | **REUSE** | Crate is already a workspace dep (Story 1.13 `keychain/mac.rs`). Same API pattern, just different `service` string and empty `account`. No new crate added |
