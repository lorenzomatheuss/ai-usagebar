# Story 3.3 — AccountPicker.swift (inline sheet slide-up + swap via TorvenCoreBridge)

## Story (User Story)

Como usuário do Torven com multi-account configurado em pelo menos um vendor (ex: 2 keys OpenRouter por contexto trabalho/pessoal), eu quero tocar no `VendorCard` desse vendor e ver subir um **inline sheet** (slide-up, padrão macOS, dentro do mesmo popover) listando os accounts disponíveis com o currently active marcado — e ao escolher um diferente, o card refletir a troca persistida via `TorvenCoreBridge` (sem fechar o popover), para que a Wave 3 entregue a feature funcional FR-6 (multi-account swap) no shape definido pelo Lorenzo no kickoff Wave 3 (inline sheet, NÃO ZStack overlay).

### Por que "Inline sheet" e não ZStack overlay

Decisão Lorenzo cravada no kickoff Wave 3:
> "AccountPicker shape em 3.3: **Inline sheet** (slide-up sobre o card, padrão macOS)"

Inline sheet usa o modifier `.sheet(isPresented:)` nativo do SwiftUI. Comportamento:
- Sobe slide-from-bottom dentro do mesmo popover (não escapa o frame do popover)
- Padrão visual macOS (mesma animação que system sheets)
- Acessibilidade automática (VoiceOver, Reduce Motion via env)

ZStack overlay seria: `ZStack { popoverContent; if showPicker { AccountPickerOverlay() } }` — mais customizável mas:
- Não tem dismiss-on-outside-tap padrão (precisa implementar)
- Não tem animação slide-from-bottom padrão (precisa implementar)
- Não respeita Reduce Motion automatic

**Trade-off ZStack vs sheet:** flexibilidade visual (ZStack) vs adesão a padrão macOS (sheet). Lorenzo escolheu sheet → adesão a padrão.

### macOS 13 vs 14+ — `.presentationDetents`

`.presentationDetents([.medium])` é macOS 14+. Para macOS 13 (deployment target estabelecido em Story 1.1), o sheet usa altura default que SwiftUI calcula a partir do content.

**Implicação:** sheet em macOS 13 pode subir mais que o necessário. Se isso for visualmente ruim em smoke run, @dev tem 2 opções:
1. Aceitar (Wave 3 escopo) e abrir nota Wave 4 para presentationDetents quando bumpar target
2. Custom slide com offset/animation (mais código, fora do escopo simples)

Default: **opção 1**.

### Reduce Motion — implementação detalhada

```swift
@Environment(\.accessibilityReduceMotion) var reduceMotion

var body: some View {
    VStack { /* ... */ }
        .transition(reduceMotion ? .opacity : .move(edge: .bottom))
        .animation(reduceMotion ? .linear(duration: 0.1) : .default, value: showPicker)
}
```

Observado: o modifier `.sheet()` no SwiftUI macOS NÃO expõe um override de transition diretamente (ele controla a apresentação interna). O `.transition` acima é sobre conteúdo dentro do sheet — afeta o que aparece, não a animação do sheet em si.

**Pragmática:** o sheet do macOS nativo já respeita Reduce Motion automaticamente em parte (não fade-out, mas duração reduzida). Esta story documenta o esforço explícito de transition no content; QA aceita se o smoke run com Reduce Motion ON não exibe slide perceptível.
