## Story (User Story)

Como desenvolvedor do Torven, eu quero um workflow CI básico em `.github/workflows/ci.yml` que executa `cargo test --workspace`, `cargo clippy --all-targets -- -D warnings` e `cargo machete` em um Ubuntu runner a cada PR, e um scaffold de `xcodebuild` em macOS runner (sem sign obrigatório), para que regressões de qualidade Rust sejam detectadas automaticamente sem bloquear PRs por issues de assinatura Apple.

---

## Contexto e Motivação

As stories do Grupo 1 estão sendo desenvolvidas sem CI automático. Antes de avançar para as stories de UI do Grupo 2, precisamos de um gate de qualidade mínimo que:

1. **Rust:** `cargo test` + `cargo clippy` + `cargo machete` em Linux (rápido, sem Xcode)
2. **Swift/Xcode:** scaffold de `xcodebuild` em macOS runner (valida que o projeto compila — sem notarização ainda)

A Story 1.26 pode começar logo após Story 1.1 completar (só precisa do workspace existindo). Pode rodar em paralelo com toda a thread de foundation.

**Referência:** `docs/architecture/torven-v1-adr.md#4-cleanup-plan` (`.github/workflows/ci.yml` NEW) e `CLAUDE.md` (gate antes de tagging).

## Acceptance Criteria

**AC-1:** `.github/workflows/ci.yml` existe e é ativado em `pull_request` para branches `main` e `develop`.

**AC-2:** Job `rust-quality` roda em `ubuntu-latest`:
- `cargo test --workspace` — deve passar (todos os testes do workspace)
- `cargo clippy --all-targets -- -D warnings` — deve passar sem warnings tratados como erros
- `cargo machete` — deve passar (sem dependências não usadas)

**AC-3:** Job `rust-quality` usa cache de `~/.cargo` e `target/` via `actions/cache` — reduz tempo de CI de ~5min para ~2min em runs subsequentes.

**AC-4:** Job `xcode-scaffold` roda em `macos-14` (Apple Silicon runner):
- Instala `xcodegen` via `brew install xcodegen`
- Roda `cd apple && xcodegen generate`
- Roda `xcodebuild -project apple/Torven.xcodeproj -scheme Torven -configuration Debug build CODE_SIGN_IDENTITY="" CODE_SIGNING_REQUIRED=NO`
- Job é marcado como `continue-on-error: true` nesta story (remove em Story 1.27 quando signing estiver pronto)

**AC-5:** PR checks ficam visíveis no GitHub como "rust-quality" e "xcode-scaffold" com status ✅/❌.

**AC-6:** A workflow NÃO faz `git push`, NÃO publica releases, NÃO chama notarytool — isso fica para `.github/workflows/release.yml` (Story 28 do Grupo 2).

**AC-7:** Tempo total de CI em uma PR típica: ≤ 8 minutos (rust-quality ~3min + xcode-scaffold ~5min em paralelo).

## Tasks / Subtasks

- [x] **T1 — Criar `.github/workflows/ci.yml`**
  ```yaml
  name: CI

  on:
    pull_request:
      branches: [main, develop]
    push:
      branches: [main]

  jobs:
    rust-quality:
      name: Rust Quality Gate
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4

        - name: Install Rust stable
          uses: dtolnay/rust-toolchain@stable
          with:
            components: clippy

        - name: Install cargo-machete
          run: cargo install cargo-machete --locked

        - name: Cache Cargo
          uses: actions/cache@v4
          with:
            path: |
              ~/.cargo/bin/
              ~/.cargo/registry/index/
              ~/.cargo/registry/cache/
              ~/.cargo/git/db/
              target/
            key: ${{ runner.os }}-cargo-${{ hashFiles('**/Cargo.lock') }}
            restore-keys: |
              ${{ runner.os }}-cargo-

        - name: cargo test
          run: cargo test --workspace

        - name: cargo clippy
          run: cargo clippy --all-targets -- -D warnings

        - name: cargo machete
          run: cargo machete

    xcode-scaffold:
      name: Xcode Scaffold
      runs-on: macos-14
      continue-on-error: true  # TODO: remover em Story 1.27 quando signing OK
      steps:
        - uses: actions/checkout@v4

        - name: Install Rust stable
          uses: dtolnay/rust-toolchain@stable

        - name: Install xcodegen
          run: brew install xcodegen

        - name: Build Rust core (aarch64 — Apple Silicon runner)
          run: cargo build --release --target aarch64-apple-darwin -p torven-core

        - name: Build xcframework (stub se script não implementado ainda)
          run: |
            if [ -f apple/scripts/build-xcframework.sh ]; then
              ./apple/scripts/build-xcframework.sh
            else
              echo "build-xcframework.sh not yet implemented — skip"
            fi

        - name: Generate Xcode project
          run: cd apple && xcodegen generate

        - name: Build app (no signing)
          run: |
            cd apple
            xcodebuild \
              -project Torven.xcodeproj \
              -scheme Torven \
              -configuration Debug \
              build \
              CODE_SIGN_IDENTITY="" \
              CODE_SIGNING_REQUIRED=NO \
              CODE_SIGNING_ALLOWED=NO
  ```

- **ADR cleanup plan**: `.github/workflows/ci.yml` NEW — cargo test workspace + evals (mocked) em ubuntu-latest.

### Nota sobre `aarch64-apple-darwin` no CI

O runner `macos-14` no GitHub Actions é Apple Silicon (M1/M2). Portanto:
- `cargo build --target aarch64-apple-darwin` roda nativamente (sem cross-compilation)
- `cargo build --target x86_64-apple-darwin` pode ser adicionado em story futura para validar cross-compile

### Nota sobre Xcode Signing no CI

O job `xcode-scaffold` usa `CODE_SIGN_IDENTITY=""` para compilar sem certificado. Isso é suficiente para validar que o projeto compila — não gera `.app` distribuível. A assinatura real vem na Story 27.

Flags explicadas:
- `CODE_SIGN_IDENTITY=""` — não usa nenhuma identidade de assinatura
- `CODE_SIGNING_REQUIRED=NO` — não exige assinatura
- `CODE_SIGNING_ALLOWED=NO` — nem tenta assinar

### Cache Strategy

Cache key baseada em `Cargo.lock` garante cache hit quando deps não mudaram. O target/ inclui compilação incremental — numa PR com mudanças pequenas no Rust, CI cai de ~5min para ~2min.

### Machete Mitigation Decision

**Verdict:** ACCEPTED with CONCERNS.

15 deps declared as `[package.metadata.cargo-machete] ignored` across `torven-core` (13) and `torven-tui` (2). Each entry has an inline comment pointing to the Wave 1 story that will consume the dep (1.4 extract-core, 1.6 config-migration, 1.13 history-sqlite, 1.15 ai-insights-core, 1.16 doctor CLI, 1.20 keychain).

**Why CONCERNS, not PASS:** the mitigation is honest debt declaration — but 15 ignores create a real risk of future drift if downstream stories don't actively drain the list. Approach is materially better than the alternatives (continue-on-error hides debt; removing deps breaks Story 1.1 ADR contract).

**Mandatory follow-up:** Each of stories 1.4, 1.6, 1.13, 1.15, 1.16, 1.20 MUST add to its DoD:
> `[ ] Remove consumed dependency from crates/{crate}/Cargo.toml [package.metadata.cargo-machete] ignored list`

QA gate on each of those stories will verify the corresponding entries were dropped. Wave 1 close-out (after Story 1.20 lands) MUST result in zero ignored entries.
