# Story 1.2 — Setup UniFFI binding tool

**Story ID:** 1.2.setup-uniffi
**Status:** Ready
**Epic:** Torven v1.0 — Pivot macOS native
**Estimated Effort:** M (1 dia, incluindo spike obrigatório 0.5d)

---

## Story (User Story)

Como desenvolvedor do Torven, eu quero o pipeline UniFFI configurado em `torven-core` com uma função de teste (`ping() -> String`) exposta via UDL e consumida em Swift, para que eu possa validar que a cadeia Rust → FFI → Swift funciona de ponta a ponta antes de expor funções de negócio reais.

---

## Contexto e Motivação

O pivô SwiftUI+Rust exige uma ponte FFI entre o Rust core e o app Swift. A escolha arquitetural é UniFFI (Mozilla) — framework battle-tested em Firefox iOS, Mullvad VPN, Matrix Element iOS.

Esta story executa o **spike obrigatório** descrito em AR-1 do ADR: validar que UniFFI funciona em macOS especificamente (não apenas iOS, que é o target primário dos exemplos oficiais) antes de construir qualquer feature real sobre ele.

**O objetivo desta story é um "hello FFI" funcional:** Swift chama `torvenCore.ping()` e recebe `"pong"`.

**Referência:** `docs/architecture/torven-v1-adr.md#adr-4` (UniFFI — decisão principal do ADR v2).

## Acceptance Criteria

**AC-1:** `uniffi = { version = "0.27", features = ["tokio"] }` adicionado em `[dependencies]` de `crates/torven-core/Cargo.toml`.

**AC-2:** `uniffi = { version = "0.27", features = ["build"] }` adicionado em `[build-dependencies]` de `crates/torven-core/Cargo.toml`.

**AC-3:** `crates/torven-core/build.rs` contém `uniffi::generate_scaffolding("src/torven_core.udl").unwrap();`.

**AC-4:** `crates/torven-core/src/torven_core.udl` existe com declaração mínima:
```udl
namespace torven_core {
    string ping();
};
```

**AC-5:** `crates/torven-core/src/uniffi_exports.rs` exporta a função `ping()` com annotation `#[uniffi::export]` (ou equivalente via `uniffi::include_scaffolding!`).

**AC-6:** `cargo build -p torven-core` completa sem erros após adição do UniFFI.

**AC-7:** O script `apple/scripts/build-xcframework.sh` existe (pode ser stub por enquanto com comentários do que fará) e documenta o fluxo de geração do `.xcframework`.

**AC-8:** Documentação inline em `torven_core.udl` explica a convenção de tipos: timestamps como `i64` (Unix), valores monetários como `f64`, erros via `[Throws=ErrorType]`.

## Dev Notes

### Architecture References

- **ADR-4** (`docs/architecture/torven-v1-adr.md#adr-4`): UniFFI vs swift-rs — UniFFI escolhido por production maturity (Firefox iOS, Mullvad VPN). Decisão de maior impacto do ADR.
- **AR-1** (`docs/architecture/torven-v1-adr.md#7-architectural-risks`): Risco de UniFFI macOS-specific gaps. Esta story é o spike obrigatório.
- **AR-3** (`docs/architecture/torven-v1-adr.md#7-architectural-risks`): Memory ownership em FFI. Mesmo no `ping()` simples, validar que retorno de String não vaza.

### Detalhes do UniFFI 0.27

- **Modo UDL (recomendado):** arquivo `.udl` declarativo + `build.rs` gera scaffolding. Este é o modo desta story.
- **Modo proc-macro (alternativo):** `#[uniffi::export]` direto no Rust sem UDL. O ADR menciona como opção mas recomenda UDL por ser mais battle-tested.
- **Tokio feature:** necessário para suporte a funções `[Async]` no UDL (será crítico na Story 1.15 — AI Insights streaming).
- **Versão 0.27:** suporta `[Async]` annotation para expor `async fn` Rust como `async throws` Swift.
