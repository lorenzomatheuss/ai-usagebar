## Story (User Story)

**As a** usuário do Torven instalado via DMG da v1.0.0,
**I want** o app verificar updates automaticamente em background, baixar de forma segura quando uma nova versão estiver disponível e me notificar discretamente na menu bar pra eu instalar com um clique,
**so that** eu fique sempre atualizado sem ter que conferir GitHub Releases manualmente — e o Lorenzo possa shippear patches/features sem precisar pedir pra cada usuário reinstalar via download manual.

---

## Contexto e Motivação

Torven é menu-bar app — usuários **não vão checar GitHub Releases**. Sparkle é o standard de-facto pra auto-update em macOS desde 2006 (usado por Sketch, Transmit, Bear, ~1000 outros apps).

**Por que Sparkle 2 (não Sparkle 1, não EdDSA-só):**
- Sparkle 2 (2.0+) suporta EdDSA signatures (mais simples, sem precisar de PEM/DSA keypair complexo) e sandboxing.
- Suporta apps com `LSUIElement: true` (menu-bar) — não força UI fullscreen pra updates.
- Distribuído via Swift Package Manager — sem CocoaPods, sem framework binary commitado no repo.

**Fluxo cravado:**
```
1. Sparkle 2 integrado via SPM (apple/Torven.xcodeproj)
2. EdDSA keypair gerado por Lorenzo:
   - SUPublicEDKey (público) → cravado em Info.plist
   - private key → ~/.ssh/torven-sparkle-ed.key (NUNCA commitado)
3. appcast.xml hospedado em GitHub Pages OU GitHub Release asset
4. Cada release (7.4) inclui:
   - Torven-X.Y.Z.dmg
   - sign_update {dmg} → ed25519 signature
   - appcast.xml atualizado com <enclosure> + sparkle:edSignature
5. App em runtime: SPUStandardUpdaterController checa SUFeedURL → encontra release nova → baixa DMG → verifica EdDSA → prompt user → instala (relaunches app)
```

**Decisões cravadas:**
- **WAVE7-D9:** Sparkle versão = 2.x (NÃO 1.x). EdDSA-only, sem DSA legacy.
- **WAVE7-D10:** appcast hosting = GitHub Release asset (cada release tem `appcast.xml` como asset, baixado de `https://github.com/lorenzomatheuss/torven/releases/latest/download/appcast.xml`). Razão: zero infraestrutura adicional, mesma source-of-truth do DMG.
- **WAVE7-D11:** SUFeedURL = `https://github.com/lorenzomatheuss/torven/releases/latest/download/appcast.xml`. GitHub redireciona `/latest/download/` pra latest tag.
- **WAVE7-D12:** Update check interval default = 86400 (24h). User pode mudar via Sparkle's automatic Settings panel (Story 7.3 wiring) — bem mais tarde, Wave 5.5 opcional.
- **WAVE7-D13:** Sparkle UI standard (não custom). `SPUStandardUpdaterController` — popup nativo do framework. Não inflar 7.3 com UI custom.

**Referências externas:**
- Sparkle docs — [Programmatic setup](https://sparkle-project.org/documentation/programmatic-setup/)
- Sparkle 2 EdDSA — [Signing updates with EdDSA](https://sparkle-project.org/documentation/eddsa-signing/)
- GitHub `/releases/latest/download/{asset}` redirect — documented behavior

## Acceptance Criteria

**AC-1:** Sparkle 2 (latest stable, `>= 2.6.0`) adicionado ao projeto Xcode via Swift Package Manager:
- Repository URL: `https://github.com/sparkle-project/Sparkle`
- Version rule: "Up to Next Major Version: 2.0.0"
- Target: linked to Torven main app (não ao TorvenCore.xcframework)
- Validar: `Sparkle.framework` aparece em `Torven.app/Contents/Frameworks/` após archive (7.2 Makefile target `make export`)

**AC-2:** `apple/Torven/Info.plist` ganha as keys Sparkle obrigatórias:
```xml
<key>SUFeedURL</key>
<string>https://github.com/lorenzomatheuss/torven/releases/latest/download/appcast.xml</string>
<key>SUPublicEDKey</key>
<string>{base64-encoded EdDSA public key gerado por Lorenzo}</string>
<key>SUEnableAutomaticChecks</key>
<true/>
<key>SUScheduledCheckInterval</key>
<integer>86400</integer>
```

**AC-3:** `apple/Torven/Updater/UpdaterController.swift` criado:
- Instancia `SPUStandardUpdaterController(startingUpdater: true, updaterDelegate: nil, userDriverDelegate: nil)`
- Singleton ou `@StateObject` em `TorvenApp.swift`
- Adiciona menu item "Check for Updates…" no popover OU no menu bar dropdown — invoca `updaterController.checkForUpdates(nil)`

**AC-4:** `TorvenApp.swift` instancia `UpdaterController` no init/onAppear — Sparkle automatic checks rodam em background sem qualquer ação adicional do user.

**AC-5:** EdDSA keypair gerado:
- Comando: `./bin/generate_keys` (vendido pelo Sparkle SPM no `Sparkle/bin/`) — gera 2 arquivos:
  - Public key → printed to stdout (base64), copiado pra `Info.plist` SUPublicEDKey (AC-2)
  - Private key → `~/.ssh/torven-sparkle-ed.key` (Lorenzo move manualmente — Sparkle gen tool grava em diretório current)
- Validar: `cat ~/.ssh/torven-sparkle-ed.key | head -1` retorna 1 linha base64 (~64 chars)
- **NUNCA commitar private key.** `.gitignore` já cobre `.ssh/*` se em `~`, mas se acidentalmente cair no repo, falhar pre-commit.

**AC-6:** Script `bin/sign-release.sh` criado:
```bash
#!/usr/bin/env bash
# Assina o DMG com EdDSA e atualiza appcast.xml para uma nova versão.
# Uso: bin/sign-release.sh <VERSION>  (ex: 1.0.0)
set -euo pipefail
VERSION=$1
DMG="build/Torven-${VERSION}.dmg"
PRIVATE_KEY="${SPARKLE_PRIVATE_KEY:-$HOME/.ssh/torven-sparkle-ed.key}"
SIGN_UPDATE_BIN="$HOME/Library/Developer/Xcode/DerivedData/.../sign_update"  # resolved at runtime
"$SIGN_UPDATE_BIN" -f "$PRIVATE_KEY" "$DMG"   # outputs: sparkle:edSignature="..." length="..."
```
Output usado pra popular `<enclosure>` no `appcast.xml`.

**AC-7:** Template `apple/appcast.template.xml` criado (committed):
```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <title>Torven</title>
    <link>https://github.com/lorenzomatheuss/torven</link>
    <description>Multi-vendor AI usage menu-bar for macOS.</description>
    <language>en</language>
    <item>
      <title>Torven {{VERSION}}</title>
      <description><![CDATA[{{RELEASE_NOTES_HTML}}]]></description>
      <pubDate>{{PUB_DATE}}</pubDate>
      <enclosure
        url="https://github.com/lorenzomatheuss/torven/releases/download/v{{VERSION}}/Torven-{{VERSION}}.dmg"
        sparkle:version="{{VERSION}}"
        sparkle:shortVersionString="{{VERSION}}"
        sparkle:minimumSystemVersion="13.0"
        length="{{DMG_SIZE_BYTES}}"
        type="application/octet-stream"
        sparkle:edSignature="{{SIGNATURE}}"/>
    </item>
  </channel>
</rss>
```

**AC-8:** Script `bin/generate-appcast.sh` criado:
```bash
#!/usr/bin/env bash
# Gera appcast.xml a partir do template + sign-release.sh output.
# Uso: bin/generate-appcast.sh <VERSION> <DMG_PATH>
# Output: build/appcast.xml
```
Substitui `{{VERSION}}`, `{{PUB_DATE}}` (RFC 822), `{{DMG_SIZE_BYTES}}` (`stat -f%z`), `{{SIGNATURE}}` (do sign-release.sh), `{{RELEASE_NOTES_HTML}}` (extraído de `CHANGELOG.md` section da versão, convertido via `pandoc` ou equivalente simples — fallback: plain text dentro `<![CDATA[]]>`).

**AC-9:** `Makefile` ganha 2 targets novos (estendendo 7.2):
- `make sparkle-sign` (depende `dmg`) → executa `bin/sign-release.sh $(VERSION)`
- `make appcast` (depende `sparkle-sign`) → executa `bin/generate-appcast.sh $(VERSION) build/Torven-$(VERSION).dmg`
- Target `make release` atualizado pra incluir `appcast` no final do pipeline (depois de `verify`)

**AC-10:** `docs/SIGNING.md` ganha seção "Sparkle update signing":
- Como gerar EdDSA keypair (AC-5)
- Como gravar private key seguramente (`~/.ssh/torven-sparkle-ed.key`, `chmod 600`)
- Como verificar signature de um DMG: `sign_update -p {public_key_base64} {dmg} {signature}`
- Troubleshooting: `SUFeedURL` returning 404 — confirmar appcast.xml está em release latest

**AC-11:** Smoke test end-to-end (manual, Lorenzo bench):

- Subir manualmente como pre-release GitHub: include `Torven-0.5.0-dev-test1.dmg` + `appcast.xml`

## Dev Notes

### Constraints técnicas

- **Sparkle `sign_update` binary path:** o tool fica em `~/Library/Developer/Xcode/DerivedData/Torven-{hash}/SourcePackages/artifacts/sparkle/Sparkle/bin/sign_update` após SPM resolve. Script `sign-release.sh` deve **descobrir** isso (via `find` ou env var) — não hardcodar o hash.
- **Sparkle requer macOS 10.13+:** Torven já mira 13.0+ (definido em Xcode), OK.
- **`SUFeedURL` HTTPS obrigatório:** GitHub é HTTPS por padrão. OK.
- **EdDSA signature length:** ~88 chars base64. Validar no template substitution.
- **`appcast.xml` é o **único** artifact que define "qual é a latest":** se 7.4 CI sobe DMG mas esquece appcast, usuários nunca pegam update. Story 7.4 deve fail-fast se appcast missing.
- **`sparkle:minimumSystemVersion`:** cravado em 13.0 (mesmo que `MACOSX_DEPLOYMENT_TARGET`). Bump se algum dia subir.
- **Auto-launch após install:** Sparkle 2 default — sem config adicional.

### Riscos identificados

| ID | Risco | Mitigação |
|---|---|---|
| R7.3-1 | EdDSA private key vazada → atacante pode signar updates maliciosos | `.gitignore` defensiva; pre-commit hook opcional; `~/.ssh/` storage (não no repo) |
| R7.3-2 | First-release "circular dep" — appcast aponta pra v1.0.0 que ainda não existe | OK por design: GitHub `/latest/download/` 404 até primeira release published. App handles 404 graciosamente (sem update disponível). |
| R7.3-3 | DMG signature mismatch após re-upload | `make appcast` regenera sempre — não cachear |
| R7.3-4 | Sparkle quebra em macOS major (Sequoia → ?) | Sparkle 2 ativamente mantido; bump via Dependabot ou manual quando OS atualizar |
| R7.3-5 | User com app standalone fora de `/Applications` (ex: Downloads) | Sparkle 2 prompt user pra mover; aceitar como caveat documentado |
