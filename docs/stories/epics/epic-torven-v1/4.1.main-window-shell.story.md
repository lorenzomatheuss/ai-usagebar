# Story 4.1 — Main Window shell + invocação dupla (popover button + cmd+1)

**Story ID:** 4.1.main-window-shell
**Status:** InReview

**Estimated Effort:** M (~1 dia — NSWindowController singleton + KeyboardShortcuts SPM + Button no popover + permission handling)

## Story (User Story)

Como usuário do Torven que quer ver o histórico detalhado de uso, eu quero poder abrir a janela principal clicando no botão "Show History…" no popover ou usando o atalho global ⌘1, para que eu consiga acessar os gráficos e dados históricos tanto de forma discoverable (botão visível) quanto de forma rápida como power user (hotkey global mesmo com o app em background).

---

## Contexto e Motivação

O popover Wave 3 exibe os vendor cards com dados em tempo real, mas não tem janela separada para histórico. A Wave 4 introduz essa janela ("Main Window") que hospedará os gráficos Swift Charts (Stories 4.3-4.6). Esta story cria o **shell** — a estrutura de invocação e o container vazio — que as stories seguintes vão preencher com conteúdo.

**Decisão WAVE4-D1 (cravada):** Invocação = botão "Show History…" no popover (discoverable para novos users) + cmd+1 global hotkey via `KeyboardShortcuts` (sindresorhus, SPM). Padrão Slack/Linear — ambos os vetores de entrada.

**Decisão WAVE4-D5 (cravada):** `KeyboardShortcuts` (sindresorhus, SPM) — não Carbon/NSEvent custom. Package mainstream, mantido, evita ~200 LOC de boilerplate.

**Por que NSWindowController singleton:**
- Múltiplos cliques em "Show History…" ou múltiplas pressões de ⌘1 não devem abrir múltiplas janelas
- `NSWindowController` com `shared` singleton pattern é o idioma macOS correto para document-less utility windows
- `NSWindow autosaveName` garante que a posição/tamanho da janela é preservada automaticamente pelo sistema

**Referências ADR:**
- `docs/architecture/torven-v1-adr.md` ADR-6 — Swift Charts (framework da janela principal)
- `docs/architecture/torven-v1-adr.md` §4 — estrutura de diretórios `apple/Torven/MainWindow/`
- `docs/architecture/torven-v1-adr.md` §8 — UX question sobre invocação da main window (fechada via WAVE4-D1)

## Acceptance Criteria

**AC-1:** SPM dependency `KeyboardShortcuts` (sindresorhus/KeyboardShortcuts) adicionada ao projeto:
- Versão `>=2.0.0` (compatível com macOS 13+)
- Adicionada via `apple/project.yml` (campo `packages:`) para XcodeGen regenerar o `.xcodeproj`
- Confirmar que `import KeyboardShortcuts` compila sem erro após `xcodegen generate`

**AC-2:** `apple/Torven/MainWindow/MainWindowController.swift` criado com:
- Classe `MainWindowController: NSWindowController` com `static let shared = MainWindowController()`
- Inicializa `NSWindow` com: `styleMask = [.titled, .closable, .miniaturizable, .resizable]`, título "Torven — History", tamanho inicial `NSRect(x: 0, y: 0, width: 900, height: 600)`
- `window?.autosaveName = "TorvenMainWindow"` para persistência automática de posição/tamanho
- Método público `func show()`: chama `showWindow(nil)` + `NSApp.activate(ignoringOtherApps: true)` + `window?.makeKeyAndOrderFront(nil)`
- `windowShouldClose` delegate retorna `false` e chama `window?.orderOut(nil)` — close esconde, não desaloca
- Conteúdo inicial: `NSHostingView` wrapping `MainWindowView()`

**AC-3:** `apple/Torven/MainWindow/MainWindowView.swift` criado como placeholder shell:
- Struct `MainWindowView: View` com `body` exibindo `Text("History — Wave 4")` centralizado
- Header comment explicando que o conteúdo real entra nas Stories 4.2-4.6
- `#Preview` opcional com frame 900×600

**AC-4:** `apple/Torven/Popover/PopoverView.swift` atualizado com botão no rodapé:
- Botão "Show History…" adicionado abaixo dos vendor cards (antes do `Spacer()` final ou em HStack de rodapé)
- `action: { MainWindowController.shared.show() }`
- Estilo: `.buttonStyle(.plain)` com `.font(.footnote)` e `.foregroundColor(.secondary)` — discreto mas visível
- Layout não quebra o frame do popover (380×540 pós-Wave 3)

**AC-5:** `apple/Torven/TorvenApp.swift` registra a hotkey global:
- `KeyboardShortcuts.Name.openMainWindow` definida como extensão em arquivo de extensões ou no próprio `TorvenApp.swift`
- `KeyboardShortcuts.onKeyUp(for: .openMainWindow) { MainWindowController.shared.show() }` registrada no `init()` ou `applicationDidFinishLaunching`
- Default shortcut: `⌘1` (KeyboardShortcuts usa `KeyboardShortcuts.Shortcut(.one, modifiers: .command)`)

**AC-6:** Hotkey funciona com app em background — pressionar ⌘1 quando outra app está em foco abre/traz ao foco a Main Window do Torven.

**AC-7:** Idempotência — múltiplas chamadas a `MainWindowController.shared.show()` (seja via botão ou hotkey) não abrem janelas duplicadas; traz a janela já existente ao foco.

**AC-8:** Window close (⌘W ou botão vermelho) esconde a janela mas NÃO a desaloca — `windowShouldClose` intercepta e chama `orderOut` em vez de `close` real. Reabertura posterior mostra janela com conteúdo preservado (posição, tamanho via autosave).

**AC-9:** `accessibilityReduceMotion` respeitado: se a janela usar animação de fade-in no `show()`, verificar `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` e usar `makeKeyAndOrderFront` sem animação custom se true. Janela padrão macOS sem animação custom já satisfaz este AC naturalmente.

**AC-10:** Build verde:

```bash
make build-core && cd apple && xcodegen generate && \
  DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project Torven.xcodeproj -scheme Torven -configuration Debug build
```

## Risks

| Risco | Severidade | Mitigação |
|---|---|---|
| macOS 14+ Accessibility permission para hotkey global (Accessibility API) | Medium | macOS 13 hotkey via `KeyboardShortcuts` usa `CGEventTap` que pode exigir Accessibility permission. Documentar no primeiro run que o usuário verá alerta de permissão; app funciona sem hotkey (botão popover ainda disponível). Graceful degradation: se permissão negada, `KeyboardShortcuts` silencia o handler sem crash. |
| KeyboardShortcuts SPM dep adiciona bundle size (~50KB) | Low | Aceito (D5 cravado). Verificar no Instruments que não há regressão em launch time. |
| `NSWindowController` singleton inicializado antes do `NSApp` estar pronto | Low | Usar lazy init ou checar `NSApp.isRunning` antes de chamar `show()`; ou adirir `NSApplicationDelegate.applicationDidFinishLaunching` para registrar handler |
| Conflito de ⌘1 com outra app quando Torven está em background | Low | `KeyboardShortcuts` é best-effort em background; se outra app capturar o evento primeiro, o handler não dispara. Comportamento esperado e documentado. |
| `NSHostingView` + SwiftUI previews em `MainWindowView`: `#Preview` pode falhar se `TorvenCoreBridge` não estiver mockado | Low | Placeholder não usa `@EnvironmentObject` — `Text("History — Wave 4")` não precisa de mock |
