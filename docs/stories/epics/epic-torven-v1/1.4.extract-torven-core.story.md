# Story 1.4 — Migrate format.rs + Extrair torven-core lib (mover vendors e módulos core)

**Story ID:** 1.4.extract-torven-core
**Status:** Draft
**Epic:** Torven v1.0 — Pivot macOS native
**Estimated Effort:** M (1 dia)

---

## Story (User Story)

Como desenvolvedor do Torven, eu quero mover todo o código reaproveitável de `src/` para `crates/torven-core/src/`, migrar `format.rs` de saída Pango para `RawMetrics` cross-platform, e garantir que o crate `torven-tui` ainda builda corretamente dependendo do `torven-core`, para que o workspace Cargo esteja na estrutura final com separação limpa entre core e UI.

---

## Contexto e Motivação

Após a Story 1.3 (cleanup), `src/` contém apenas os módulos válidos. Esta story move tudo para `crates/torven-core/src/` e faz a migração de `format.rs` de strings Pango para structs semânticas.

Dois movimentos principais:

1. **Física do código:** mover `src/{anthropic,openai,...,cache,countdown,error,pacing,usage,vendor,config,format,tui}` → `crates/torven-core/src/vendors/` e `crates/torven-core/src/`
2. **Refactor de format.rs:** substituir `FormattedSnapshot` com markup Pango por `RawMetrics { cost_usd, pct_used, tokens_used, label_kind }` — Swift formata a string final; TUI tem helper próprio

**Referência:** `docs/architecture/preservation-map.md#migrate` e `docs/architecture/torven-v1-adr.md#4-cleanup-plan`.

---

## Acceptance Criteria

**AC-1:** Todos os módulos vendor (`anthropic`, `openai`, `openrouter`, `zai`, `gemini`) existem em `crates/torven-core/src/vendors/` com imports atualizados para o novo caminho.

**AC-2:** Módulos core (`cache.rs`, `countdown.rs`, `error.rs`, `pacing.rs`, `usage.rs`, `vendor.rs`) existem em `crates/torven-core/src/`.

**AC-3:** `config.rs` existe em `crates/torven-core/src/` (mover sem alterar conteúdo — o refactor de conteúdo é na Story 1.6).

**AC-4:** `format.rs` em `crates/torven-core/src/` retorna `RawMetrics` (sem qualquer string Pango, sem markup HTML):
```rust
pub struct RawMetrics {
    pub cost_usd: Option<f64>,
    pub pct_used: Option<f64>,
    pub tokens_used: Option<u64>,
    pub label_kind: LabelKind,
}

pub enum LabelKind {
    PercentOfWindow,
    MessagesQuota,
    UsdSpent,
    OAuthUnlinked,
}
```

**AC-5:** `crates/torven-tui/` contém `src/format_tui.rs` com helpers de formatação específicos do TUI (string Pango/ratatui). O TUI ainda builda e funciona corretamente.

**AC-6:** `src/tui/` movido para `crates/torven-tui/src/` com imports atualizados para `torven_core::*`.

**AC-7:** `cargo build --workspace` completa sem erros. `cargo test --workspace` (todos os testes existentes) passam.

**AC-8:** `src/` original fica vazio ou removido — todo o código migrado. `Cargo.toml` raiz continua como workspace manifest sem crate próprio.

### Mudança Crítica em format.rs

O `format.rs` atual gera strings Pango com markup:
```rust
// ANTES (Waybar):
pub fn format_cost(usd: f64) -> String {
    format!("<span color='#ff0000'>${:.2}</span>", usd)  // Pango markup — DELETE
}
```

Após a migração:
```rust
// DEPOIS (cross-platform):
pub fn compute_metrics(snapshot: &VendorSnapshot) -> RawMetrics {
    RawMetrics {
        cost_usd: snapshot.cost_usd,
        pct_used: snapshot.pct_used,
        label_kind: LabelKind::UsdSpent,
        // ...
    }
}
```

O Swift decide a cor (via `Color.calm`, `Color.amber`, `Color.critical` em Assets.xcassets). O TUI decide o markup ratatui via `format_tui.rs`.
