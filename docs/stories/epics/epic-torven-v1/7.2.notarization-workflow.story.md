## Story (User Story)

**As a** Torven maintainer prestes a publicar a v1.0.0,
**I want** um pipeline local reprodutível que assina, empacota em DMG, submete pra Apple notarization, faz staple do ticket e verifica Gatekeeper acceptance,

## Contexto e Motivação

Story 7.1 entrega `.xcarchive` assinada com Developer ID Application. Esta story transforma isso num `.dmg` notarizado e stapled.

**Por que DMG, não ZIP?**
- DMG é o formato esperado por usuários macOS que clicam "Download" no GitHub Release
- DMG suporta layout custom (background, drag-to-Applications hint) — Sparkle (Story 7.3) também tem melhor UX com DMG
- Notarization aceita tanto ZIP quanto DMG; mas stapler **só faz staple em DMG ou .app** (não em ZIP). Stapled ticket é essencial pra abrir offline.

**Pipeline alvo (alvo `make release`):**
```
1. xcodebuild archive          (Story 7.1 — re-execução pra release atual)
2. xcodebuild -exportArchive   → Torven.app
3. create-dmg                  → Torven-1.0.0.dmg
4. xcrun notarytool submit ... --wait → status: Accepted
5. xcrun stapler staple Torven-1.0.0.dmg
6. spctl -a -t open --context context:primary-signature -v Torven-1.0.0.dmg → "accepted"
```

**Decisões cravadas:**
- **WAVE7-D5:** Empacotamento = DMG, não ZIP. Razão: stapler + UX.
- **WAVE7-D6:** `create-dmg` (script bash padrão de comunidade — https://github.com/create-dmg/create-dmg) instalável via `brew install create-dmg`. Não inventar packaging próprio.
- **WAVE7-D7:** `make release` é o único entry point — não chamar `xcodebuild` diretamente fora do Makefile. Faz CI (7.4) e local-build idênticos.
- **WAVE7-D8:** Notarization timeout = 30 min (default `--wait`). Se exceder, falhar fast com clear error.

**Referências externas:**
- Apple — [Resolving common notarization issues](https://developer.apple.com/documentation/security/resolving-common-notarization-issues)
- create-dmg README — opções `--volname`, `--window-size`, `--icon-size`, `--app-drop-link`

## Acceptance Criteria

**AC-1:** `Makefile` (raiz do repo) ganha 4 targets novos:
- `make archive` → `xcodebuild -project apple/Torven.xcodeproj -scheme Torven -configuration Release -archivePath build/Torven.xcarchive archive` (consome `Local.xcconfig` da 7.1)
- `make export` → `xcodebuild -exportArchive -archivePath build/Torven.xcarchive -exportPath build/export -exportOptionsPlist apple/ExportOptions.plist` (depende `archive`)
- `make dmg` → `create-dmg --volname "Torven 1.0.0" --window-size 540 380 --icon-size 100 --app-drop-link 380 200 --hide-extension Torven.app build/Torven-1.0.0.dmg build/export/Torven.app` (depende `export`)
- `make release` → encadeia `dmg` → `notarize` → `staple` → `verify` (depende todos)

**AC-2:** `apple/ExportOptions.plist` criado com:
```xml
<key>method</key><string>developer-id</string>
<key>destination</key><string>export</string>
<key>signingStyle</key><string>automatic</string>
<key>teamID</key><string>$(DEVELOPMENT_TEAM)</string>
```

**AC-3:** Target `make notarize` chama:
```bash
xcrun notarytool submit build/Torven-$(VERSION).dmg \
  --keychain-profile torven-notarytool \
  --wait \
  --output-format json | tee build/notarization-log.json
```
Falha o build se exit code ≠ 0 ou `.status != "Accepted"` no JSON.

**AC-4:** Target `make staple` chama:
```bash
xcrun stapler staple build/Torven-$(VERSION).dmg
```
Falha se stapler retornar ≠ 0.

**AC-5:** Target `make verify` chama:
```bash
spctl -a -t open --context context:primary-signature -v build/Torven-$(VERSION).dmg
codesign -dv --verbose=4 build/export/Torven.app
xcrun stapler validate build/Torven-$(VERSION).dmg
```
Falha se `spctl` não retornar `accepted` ou `source=Notarized Developer ID`.

**AC-6:** `VERSION` variável do Makefile = lido de `Cargo.toml` workspace version (top-level), via:
```makefile
VERSION := $(shell grep '^version' Cargo.toml | head -1 | sed -E 's/version = "(.*)"/\1/')
```
Story 7.6 vai bumpar de `0.5.0-dev` → `1.0.0`, então `make release` produz `Torven-1.0.0.dmg` automaticamente.

**AC-7:** `make clean-release` remove `build/` (idempotente).

**AC-8:** `docs/SIGNING.md` (criado na 7.1) ganha seção "Building a release locally":
- Pré-req: `brew install create-dmg`
- `make release VERSION=1.0.0` (override opcional)
- Outputs esperados: `build/Torven-1.0.0.dmg` + `build/notarization-log.json`
- Tempo esperado: 5-15 min (notarization 90% do tempo)

**AC-9:** Smoke test local (não em CI ainda — 7.4 cobre): `make release` em bench session do Lorenzo produz DMG válido. Verificação manual:
- Abrir DMG num Finder limpo (não-`xattr` removed) — sem warning Gatekeeper
- Arrastar `Torven.app` pra `/Applications`
- `open /Applications/Torven.app` — abre sem prompt, menu bar item aparece

**AC-10:** Makefile target `make help` (ou comentário no header) lista os novos targets com 1-linha de descrição cada.

## Dev Notes

### Constraints técnicas

- **`create-dmg` requer Homebrew:** `brew install create-dmg`. Story 7.4 (CI) precisa instalar no runner (`brew install create-dmg` no setup step).
- **`--wait` flag bloqueia até `Accepted` ou `Rejected`:** Apple's median notarization é ~5 min, p95 ~15 min. Timeout default suficiente (30 min). Se exceder → CI fail é ok, dev re-roda.
- **Notarization log:** se `status: Rejected`, `xcrun notarytool log <submission-id> --keychain-profile torven-notarytool` retorna JSON com `issues[]`. Documentar em SIGNING.md como troubleshootar.
- **Stapler offline check:** após staple, o DMG pode abrir mesmo sem internet (Gatekeeper consulta ticket localmente). Sem staple, Gatekeeper precisa consultar Apple online → primeira abertura offline falha. Stapling é **essencial** pra UX.
- **`spctl` é mais rígido que double-click do Finder:** se passa `spctl -a -t open --context context:primary-signature`, passa qualquer Mac. Esse é o gate-of-record.
