# Story 1.15 — AI Insights core: Anthropic client + tool_use + streaming callback

**Story ID:** 1.15.ai-insights-core
**Status:** Ready
**Epic:** Torven v1.0 — Pivot macOS native
**Estimated Effort:** L (1.5-2 dias, incluindo spike async FFI 0.5d)

---

## Story (User Story)

Como desenvolvedor do Torven, eu quero o módulo `insights` em `torven-core` com cliente Anthropic Messages API operando em `tool_use` mode com streaming, trait `LlmClient` com implementação real e mock, `prompts/insights.v1.md` com o primeiro prompt versionado, budget guards de custo/latência, e callback interface FFI para streaming de tokens para Swift, para que o backend de AI Insights esteja pronto para consumo pelo SwiftUI (Story 1.19 do Grupo 2).

---

## Contexto e Motivação

FR-7 do PRD é o diferenciador central do Torven: AI Insights com eval pipeline público, prompts versionados e structured outputs. Esta story entrega o backend inteiro em Rust — o lado Swift (InsightsPanel.swift) vem na Story 1.19 do Grupo 2.

Elementos críticos:
1. **Anthropic tool_use mode** — mais robusto que prompted JSON para structured outputs em Claude 3.5+ (ADR-7)
2. **Streaming via callback interface UniFFI** — tokens chegam token a token para o Swift (AR-2 spike obrigatório)
3. **tokio runtime como `OnceCell`** — shared com FFI context, single-thread para macOS sandbox safety
4. **Privacy redaction** — payload enviado para Anthropic nunca contém api_keys nem account names

**Referência:** `docs/architecture/torven-v1-adr.md#adr-7` (tool_use mode) e `docs/prd/torven-v1.md#6-ai-insights`.

**AC-3:** Trait `LlmClient` em `insights/llm_client.rs`:

    async fn request_insight_streaming(

Com implementações `RealAnthropicClient` e `MockLlmClient`.

**AC-4:** `InsightsContext` struct definida com campos de privacidade (sem api_keys, sem account names — apenas aggregates):
```rust
pub struct InsightsContext {
    pub usage_payload: Vec<VendorAggregate>,  // apenas numérico
    pub since_days: u32,
    pub prompt_version: String,
}
```

**AC-5:** Budget guards implementados em `insights/budget.rs`:
- Input token count estimado antes de enviar; acima de 8000 tokens retorna `InsightsError::InputBudgetExceeded`
- `max_tokens = 1000` no request Anthropic
- Timeout de 15s no request; acima retorna `InsightsError::Timeout`
- Rate limit: 1 request por minuto por instância do client (via `tokio::time::Instant`)

**AC-6:** Streaming callback interface declarada no UDL:
```udl
callback interface InsightsCallback {
    void on_token(string token);
    void on_done(InsightsOutput output);
    void on_error(string error);
};
```

**AC-7:** `InsightsOutput` struct exposta via UDL como `dictionary`:
```udl
dictionary InsightsOutput {
    string headline;
    sequence<InsightItem> insights;
    string recommendation;
    f64 cost_usd;
    i64 latency_ms;
    string prompt_version;
};
```

**AC-8:** Tokio runtime compartilhado via `OnceCell<Runtime>` em `crates/torven-core/src/runtime.rs` com `new_current_thread()` (não multi-thread — ADR-7 nota sobre sandbox macOS).

**AC-9:** Testes de integração em `crates/torven-core/tests/insights_e2e.rs` com `MockLlmClient`:
- `test_insights_with_mock()`: chama `request_insight_streaming` com mock, valida callback `on_done` recebido com output válido
- `test_budget_exceeded()`: context com payload acima de 8000 tokens retorna `InsightsError::InputBudgetExceeded`
- `test_privacy_no_api_keys()`: payload de `InsightsContext` não contém api_key (verificar campos)

## Dev Notes

### Architecture References

- **ADR-7** (`docs/architecture/torven-v1-adr.md#adr-7`): Anthropic tool_use mode. Streaming flow detalhado (Swift UI → Rust → Anthropic → callback). Tokio `OnceCell` com `new_current_thread()`. Cancellation via `tokio::sync::oneshot`.
- **ADR-4** (`docs/architecture/torven-v1-adr.md#adr-4`): `callback interface InsightsCallback` no UDL. `[Async]` annotation. Memory safety via UniFFI reference counting.
- **AR-2** (`docs/architecture/torven-v1-adr.md#7-architectural-risks`): Tokio runtime em FFI context. Spike de 0.5d obrigatório nesta story para validar cancellation.
- **PRD §6** (`docs/prd/torven-v1.md#6-ai-insights`): Eval pipeline, prompt versioning, cost budgets, privacy payload spec.

### Streaming Flow Completo (do ADR-7)

```
Swift await coreBridge.requestInsights(context, callback: self)
     ↓ UniFFI [Async]
Rust: insights::client::run_streaming(context, callback)
     ↓ tokio runtime (get_runtime().block_on(...))
HTTP POST Anthropic streaming
     ↓ per chunk: callback.on_token(partial_json)
     ↓ message_stop: parse JSON + validate schema
     ↓ callback.on_done(InsightsOutput)
```

### Privacy do Payload (PRD §6.5)

O `InsightsContext.usage_payload` enviado para Anthropic NÃO deve conter:
- `api_key` de nenhum vendor
- Nome de accounts/clientes em plaintext
- Prompts ou outputs reais do usuário

Deve conter APENAS:
- Agregados numéricos por vendor (tokens, custo, janela temporal)
- Tags genéricas (`client`, `personal`, `team`)
- Histogramas horários dos últimos N dias

A `account_id` no payload é `sha256(vendor_id + account_name)[..8]` — determinístico mas não reversível.

## Risk: AR-2 — Tokio runtime em FFI context

**Severidade:** MEDIUM-HIGH

O runtime `new_current_thread()` deve ser testado com cancellation mid-stream. Se o Swift cancelar a task e o tokio task ficar órfão, vira memory leak + CPU waste. O spike desta story valida isso com o MockLlmClient antes de testar com a API real.
