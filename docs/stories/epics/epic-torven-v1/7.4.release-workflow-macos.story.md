## Story (User Story)

**As a** maintainer publicando um release Torven,
**I want** o push de uma tag `vX.Y.Z` ativar um GitHub Actions workflow que builda, assina, notariza, empacota em DMG, gera appcast.xml e publica tudo num GitHub Release — sem nenhuma ação manual em runners local,
**so that** releases sejam reprodutíveis, auditáveis e disparáveis a partir de qualquer dev machine (apenas `git push origin vX.Y.Z`).

---

## Contexto e Motivação

`.github/workflows/release.yml` atualmente é **legacy Linux/Waybar/AUR**:
- Builda 3 targets: `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `aarch64-apple-darwin`
- Produz tarballs com binários CLI (`torven`, `torven-tui`)
- Release body referencia AUR (`yay -S torven-bin`) — `packaging/aur/` foi removido na Story 1.3
- **Não builda `.app`**, **não assina**, **não notariza**, **não gera appcast**

Esta story **reescreve** o workflow pra:
- Disparar em tag `v*` (mantido)
- Builda **só macOS aarch64** (Torven é arm64-only por design v1.0)
- Builda `.app` via `make release` (Stories 7.1-7.3 dependências)
- Publica `Torven-X.Y.Z.dmg` + `appcast.xml` + `SHA256SUMS.txt` no GitHub Release

**Decisões cravadas:**
- **WAVE7-D14:** Workflow corre em `macos-14` runner (Apple Silicon GitHub-hosted). Sem self-hosted — caro pra projeto solo.
- **WAVE7-D15:** Single-target build: aarch64-apple-darwin. Sem Linux. Sem Universal Binary.
- **WAVE7-D16:** Versão da tag (`v1.0.0`) → Cargo.toml workspace version (deve estar `1.0.0` antes de push). Workflow valida via `grep`; bloqueia se mismatch.
- **WAVE7-D17:** Sparkle private key passada via secret `SPARKLE_PRIVATE_KEY` (base64 do arquivo). Workflow grava em tempfile pra `make appcast` consumir.
- **WAVE7-D18:** Developer ID Application cert passada via secrets `APPLE_DEVELOPER_ID_APPLICATION_CERT_BASE64` (P12 export base64) + `APPLE_DEVELOPER_ID_APPLICATION_CERT_PASSWORD`. Importada num temporary keychain pra build → keychain destruído no cleanup.
- **WAVE7-D19:** Release body é **gerado a partir do CHANGELOG.md** seção da versão (não hardcoded como atual).
- **WAVE7-D20:** Workflow é `workflow_dispatch`-able pra dry-runs em pre-release tags (`v0.5.0-dev-test1` etc).

**Referências externas:**
- GitHub Actions docs — [macOS hosted runner specs](https://docs.github.com/en/actions/using-github-hosted-runners/about-github-hosted-runners)
- Apple — [Importing certificates in CI](https://developer.apple.com/documentation/xcode/distributing-your-app-for-beta-testing-and-releases) (Xcode Cloud docs apply same patterns)

## Acceptance Criteria

**AC-1:** `.github/workflows/release.yml` reescrito:
- Trigger: `push` em tags `v*` + `workflow_dispatch` (com input `ref`)
- Single job rodando em `macos-14`
- Permissions: `contents: write`
- Steps em ordem documentada (AC-3 → AC-10)

**AC-2:** Step "Validate version matches Cargo.toml":
- Extrai version do tag (`v1.0.0` → `1.0.0`)
- Lê `version` de `Cargo.toml` workspace level
- Falha o job se diferentes — com clear error message
- Skipped quando `workflow_dispatch` (dev pode dry-run com tag fake)

**AC-3:** Step "Install dependencies":
```bash
brew install create-dmg
# Sparkle SPM sign_update binary descoberto após Xcode build
```

**AC-4:** Step "Import Developer ID Application cert":
- Cria temporary keychain: `security create-keychain -p "$KEYCHAIN_PWD" build.keychain`
- Importa cert: `echo "$APPLE_DEVELOPER_ID_APPLICATION_CERT_BASE64" | base64 -d > cert.p12 && security import cert.p12 -k build.keychain -P "$APPLE_DEVELOPER_ID_APPLICATION_CERT_PASSWORD" -T /usr/bin/codesign`
- Unlock + set default: `security unlock-keychain -p "$KEYCHAIN_PWD" build.keychain && security list-keychains -d user -s build.keychain login.keychain`
- Set partition list: `security set-key-partition-list -S apple-tool:,apple: -s -k "$KEYCHAIN_PWD" build.keychain`
- Validar: `security find-identity -p codesigning build.keychain` retorna `1 valid identities found` (Developer ID Application).

**AC-5:** Step "Create notarytool keychain profile":
```bash
xcrun notarytool store-credentials torven-notarytool \
  --apple-id "$APPLE_ID" \
  --team-id "$APPLE_TEAM_ID" \
  --password "$APPLE_APP_SPECIFIC_PASSWORD" \
  --keychain build.keychain
```

**AC-6:** Step "Setup Local.xcconfig":
```bash
cat > apple/Local.xcconfig <<EOF
DEVELOPMENT_TEAM = $APPLE_TEAM_ID
CODE_SIGN_IDENTITY = Developer ID Application
EOF
```

**AC-7:** Step "Setup Sparkle private key":
```bash
echo "$SPARKLE_PRIVATE_KEY" | base64 -d > "$HOME/.torven-sparkle-ed.key"
chmod 600 "$HOME/.torven-sparkle-ed.key"
export SPARKLE_PRIVATE_KEY="$HOME/.torven-sparkle-ed.key"
```

**AC-8:** Step "Build release" (delegated to Story 7.2/7.3 Makefile):
```bash
make release VERSION="$VERSION"
```
Output esperado em `build/`:
- `Torven-$VERSION.dmg` (signed + notarized + stapled)
- `appcast.xml`
- `notarization-log.json`

**AC-9:** Step "Generate SHA256SUMS.txt":
```bash
cd build
shasum -a 256 Torven-$VERSION.dmg appcast.xml > SHA256SUMS.txt
```

**AC-10:** Step "Generate release body from CHANGELOG":
- Extrai seção do CHANGELOG.md correspondente à versão (entre `## [$VERSION]` e próximo `## [`)
- Anexa rodapé com SHA256SUMS table
- Salva em `body.md`
- Adapt do parser atual mas troca AUR refs por DMG install instructions:
  ```markdown
  ## Install
  
  Download `Torven-{VERSION}.dmg`, abrir, arrastar para `/Applications`.
  
  Auto-updates via Sparkle (Story 7.3): app verifica novas versões em background.
  ```

**AC-11:** Step "Create/update GitHub Release":
```bash
gh release create "$TAG" \
  build/Torven-$VERSION.dmg \
  build/appcast.xml \
  build/SHA256SUMS.txt \
  --title "v$VERSION" \
  --notes-file body.md \
  --latest
```
Se `workflow_dispatch` e tag já existe, usar `gh release upload ... --clobber` (mesmo pattern do current).

**AC-12:** Step "Cleanup" (always-runs):
```bash
security delete-keychain build.keychain || true
rm -f "$HOME/.torven-sparkle-ed.key" apple/Local.xcconfig cert.p12
```

**AC-13:** Workflow secrets necessários (validar antes do dev kickoff que Lorenzo configurou em repo settings):

- `APPLE_DEVELOPER_ID_APPLICATION_CERT_PASSWORD`
- `SPARKLE_PRIVATE_KEY` (base64 do `~/.ssh/torven-sparkle-ed.key`)

**AC-14:** `docs/SIGNING.md` ganha seção "CI Setup":

**AC-15:** `make ci-release` target adicional no Makefile que **não** chama `xcrun notarytool store-credentials` (CI já configura no AC-5). Stories 7.1-7.3 Makefile assumed local profile `torven-notarytool` — CI mesmo nome no temp keychain (AC-5). `make release` funciona em ambos contextos sem branching.

## Dev Notes

### Constraints técnicas

- **macOS runner cost:** GitHub Actions cobra 10× a tarifa Linux pra macOS. Free tier 2000 min/mês Linux ≈ 200 min macOS. Para projeto solo: budget razoável (release toma ~15 min, ≈ 13 releases/mês free). Documentar em SIGNING.md.
- **Notarization async + CI timeout:** `--wait` flag bloqueia até Apple responde. CI step timeout default 6h — Apple median 5 min, OK. Hard-fail se >30 min via `timeout` wrapper opcional.
- **Cert keychain isolation:** **NUNCA** importar em `login.keychain` no runner. Sempre temporary keychain criado/deletado no run. AC-12 cleanup garante.
- **`security set-key-partition-list`:** crítico pós macOS 10.12 — sem isso, `codesign` prompta interativo no runner (que fails CI). AC-4 inclui.
- **Sparkle private key transit:** GitHub secret é encrypted at-rest, mas é exposto em variável `$SPARKLE_PRIVATE_KEY` durante step. Log masking automático cobre, mas validar no PR review.
- **`workflow_dispatch` ref input:** valida que `inputs.ref` está em formato `v*` ou aceita commit SHA (current workflow aceita ambos).
