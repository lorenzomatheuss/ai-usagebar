# Story 1.1 — Bootstrap Cargo workspace + Xcode project via XcodeGen

**Story ID:** 1.1.bootstrap-workspace
**Status:** Draft
**Epic:** Torven v1.0 — Pivot macOS native
**Estimated Effort:** M (meio dia a 1 dia)

---

## Story (User Story)

Como desenvolvedor do Torven, eu quero um workspace Cargo com múltiplos crates (`torven-core`, `torven-tui`) e um projeto Xcode gerado via XcodeGen (`apple/project.yml`), para que o Rust core e a app SwiftUI possam ser buildados independentemente com um único `make build-all`.

---

## Contexto e Motivação

O codebase atual é um crate flat em `Cargo.toml` com `src/` contendo lib + dois bins. O pivot para macOS native exige:

1. Separar o core Rust em crate lib (`torven-core`) compilável como `staticlib` para link no Xcode
2. Manter o TUI ratatui como crate bin separado (`torven-tui`)
3. Criar estrutura inicial do app Xcode via XcodeGen (YAML declarativo, gitignored `.xcodeproj`)

Esta story entrega o esqueleto que todas as outras stories do Grupo 1 precisam como base.

**Referência:** `docs/architecture/torven-v1-adr.md#adr-1` (Workspace Cargo: multi-crate split) e `docs/architecture/torven-v1-adr.md#adr-9` (XcodeGen).

---

## Acceptance Criteria

**AC-1:** `cargo build --workspace` completa sem erros após a reestruturação.

**AC-2:** `crates/torven-core/` existe como crate lib com `crate-type = ["staticlib", "rlib", "cdylib"]` declarado em `Cargo.toml`.

**AC-3:** `crates/torven-tui/` existe como crate bin com dependência em `torven-core`.

**AC-4:** `apple/project.yml` existe com configuração XcodeGen mínima: target `Torven` macOS 13.0+, `LSUIElement: true`, `MARKETING_VERSION: 1.0.0`.

**AC-5:** `xcodegen generate` executado em `apple/` produz `apple/Torven.xcodeproj/` sem erros (arquivo parseável pelo Xcode).

**AC-6:** `apple/Torven.xcodeproj/` está listado em `.gitignore`; `apple/Torven.xcodeproj/xcshareddata/xcschemes/Torven.xcscheme` está NO gitignore (commitado).

**AC-7:** `Makefile` tem targets `build-core` (cargo build torven-core release) e `build-app` (xcodegen generate + xcodebuild) documentados.

**AC-8:** O crate `crates/torven-evals/` ou `[[bin]] name="torven-evals"` existe como stub com `main.rs` mínimo (`fn main() { println!("torven-evals stub"); }`).

## Tasks / Subtasks

- [ ] **T1 — Criar workspace root `Cargo.toml`**
  - Substituir `Cargo.toml` atual por workspace manifest: `[workspace] members = ["crates/*"]`
  - Adicionar `resolver = "2"` e campos padrão de workspace (`edition`, `license`, etc.)
  - Mover campos de `[package]` atual para `crates/torven-core/Cargo.toml`

- [ ] **T2 — Criar `crates/torven-core/`**
  - Criar estrutura: `crates/torven-core/Cargo.toml`, `crates/torven-core/src/lib.rs`
  - Em `Cargo.toml`: `crate-type = ["staticlib", "rlib", "cdylib"]`
  - Copiar dependências relevantes do `Cargo.toml` atual (reqwest, tokio, serde, etc.)
  - `src/lib.rs` inicial: `pub fn ping() -> String { "torven-core".to_string() }`

- [ ] **T3 — Criar `crates/torven-tui/`**
  - Criar `crates/torven-tui/Cargo.toml` como bin com dep `torven-core = { path = "../torven-core" }`
  - `src/main.rs` stub: `fn main() { println!("torven-tui"); }`
  - (O conteúdo real de `src/tui/` será movido na Story 1.4)

- [ ] **T4 — Criar stub `torven-evals`**
  - Adicionar `[[bin]] name = "torven-evals" path = "src/bin/torven-evals.rs"` em `crates/torven-core/Cargo.toml`
  - Criar `crates/torven-core/src/bin/torven-evals.rs` com `fn main() { println!("torven-evals stub"); }`

- [ ] **T5 — Criar `apple/project.yml`**
  - Conteúdo mínimo (vide ADR-9, §3 do ADR):
    ```yaml
    name: Torven
    options:
      bundleIdPrefix: com.torven
      deploymentTarget:
        macOS: "13.0"
    settings:
      base:
        MARKETING_VERSION: "1.0.0"
        CURRENT_PROJECT_VERSION: "1"
        DEVELOPMENT_TEAM: "${DEVELOPMENT_TEAM}"
        CODE_SIGN_STYLE: Automatic
    targets:
      Torven:
        type: application
        platform: macOS
        sources:
          - path: Torven
        info:
          path: Torven/Info.plist
          properties:
            LSUIElement: true
            LSApplicationCategoryType: public.app-category.developer-tools
    ```
  - Criar `apple/Torven/TorvenApp.swift` com hello world SwiftUI `@main App`

- [ ] **T6 — Criar `apple/Torven/TorvenApp.swift` skeleton**
  ```swift
  import SwiftUI
  @main
  struct TorvenApp: App {
      var body: some Scene {
          MenuBarExtra("Torven", systemImage: "chart.bar.fill") {
              Text("Torven — hello world")
          }
          .menuBarExtraStyle(.window)
      }
  }
  ```

- [ ] **T7 — Atualizar `.gitignore`**
  - Adicionar `apple/Torven.xcodeproj/` (exceto xcshareddata/xcschemes/)
  - Adicionar `apple/Frameworks/` (xcframework gerado)
  - Adicionar `apple/Torven/Bridge/Generated/` (UniFFI output)
  - Verificar que `.env` e `*.credentials.json` já estão cobertos

- [ ] **T8 — Atualizar `Makefile`**
  - Target `build-core`: `cargo build --release --target aarch64-apple-darwin -p torven-core`
  - Target `build-app`: `cd apple && xcodegen generate && xcodebuild -scheme Torven -configuration Debug`
  - Target `build-all`: depende de `build-core build-app`
  - Target `clean`: `cargo clean && rm -rf apple/Torven.xcodeproj apple/Frameworks`

- [ ] **T9 — Verificar `cargo build --workspace` verde**
  - Rodar `cargo build --workspace` e confirmar zero erros
  - Rodar `cargo test --workspace` (pode ter 0 tests, mas não deve haver compilation errors)

- [ ] **T10 — Verificar `xcodegen generate` funciona**
  - Instalar xcodegen se não presente: `brew install xcodegen`
  - Rodar `cd apple && xcodegen generate`
  - Confirmar `.xcodeproj` é criado e parseável (abrir no Xcode ou rodar `xcodebuild -list`)
