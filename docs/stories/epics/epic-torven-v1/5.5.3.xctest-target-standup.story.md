# Story 5.5.3 — XCTest target standup + ViewModel coverage (TEST-001)

**Story ID:** 5.5.3.xctest-target-standup
**Status:** InReview
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 5.5 — Polish (carry-forwards Wave 5)

## Story (User Story)

**As a** maintainer protegendo Torven contra regressões em SwiftUI ViewModel logic,
**I want** um XCTest target funcional em `apple/Torven.xcodeproj` com cobertura inicial de SettingsViewModel, ChartViewModel e suporte preparado pra MenuBarStateProvider (Wave 7.5),
**so that** PRs futuras (especialmente Wave 7 release stories) tenham gate automatizado contra quebras em lógica de probe OAuth, reload de chart, Keychain blob round-trip e budget state mapping — sem depender de bench manual sequencial.

---

## Contexto e Motivação

`apple/Torven.xcodeproj` **não tem XCTest target**. Toda validação Swift até hoje foi **smoke manual** (Lorenzo bench). Funcionou pra Waves 1-5 com PR throughput baixo, mas dois fatos mudam a balança:

1. **Wave 7.5 (deferred) introduz `MenuBarStateProvider`** com 5 state transitions (idle/ok/warning/exceeded/refreshing) — lógica perfeita pra unit test, alto custo se quebrar (menu bar é o ponto de visibilidade primária do app).
2. **Story 5.5.2 introduz dual-source OAuth probe** com fallback paths — sem test, regressões silenciam até bench user.

**Decisões cravadas:**
- **WAVE5.5-D10:** XCTest target nome = `TorvenTests`. Bundle id = `com.torven.Torven.Tests`.
- **WAVE5.5-D11:** Cobertura inicial obrigatória: SettingsViewModel (5.5.2 surface), ChartViewModel (reload + refresh + budget mapping). **MenuBarStateProvider tests opcionais aqui** — pode ser Wave 7.5 quando o componente existe.
- **WAVE5.5-D12:** Mock Strategy = constructor injection já existente em SettingsViewModel (`fileExists` / `homeDirectoryProvider`). Estender pattern pra `keychainProvider`. **Não** introduzir biblioteca mocking externa (mockingbird, Cuckoo) — mantém DI simples.
- **WAVE5.5-D13:** CI integration via `xcodebuild test -scheme Torven -destination "platform=macOS"`. Adicionar step ao `.github/workflows/ci.yml` existente.
- **WAVE5.5-D14:** Cobertura mínima inicial = **15 testes** (5 SettingsViewModel + 8 ChartViewModel + 2 helper utilities). Não buscar 80% coverage hoje — buscar **caso-crítico coverage**.

**Referências:**
- TEST-001 origem: Story 5.2 carry-forward + 5.3 OOS
- Apple — [Adding unit tests to your existing project](https://developer.apple.com/documentation/xcode/adding-tests-to-your-existing-project)

## Dev Notes

### Constraints técnicas

- **Xcode UI vs pbxproj-manual:** adicionar XCTest target manualmente em pbxproj é error-prone (build phases, frameworks, capabilities). **Recomendado:** abrir Xcode, criar target via UI, commit do resulting pbxproj diff. Documentar no PR description.
- **Test host = main app:** permite tests acessarem internal types. Trade-off: testes não podem rodar sem main app build verde primeiro. OK pra unit tests; integration tests futuros podem usar test-host-independent.
- **Async/await em XCTest:** macOS 13+ XCTest tem `async` test methods (`func test_foo() async throws`). Use sem `expectation(...)` boilerplate antigo.
- **MainActor:** SettingsViewModel é `@MainActor`. Tests devem usar `@MainActor func test_...()` OR `await MainActor.run { ... }`. Otherwise warnings + race conditions.
- **Coverage não-blocking inicialmente:** AC-15 thresholds são informacionais. Promote pra blocking quando 5.5.4+ histórico mostrar números estáveis.
- **CI runner cost:** `macos-14` é 10× pricier que linux. Test step adds ~3 min ao CI. Aceitável pra repo pequeno; document em commit se cost se torna issue.
- **Sample fixtures:** JSON files não devem conter dados sensíveis. Use mock vendor names ("test_vendor_a") em vez de reais quando possível.

### Issues encountered & resolved

1. **xcodegen approach (not manual pbxproj edit) — R5.5.3-1 fully mitigated.** Discovered the repo uses xcodegen 2.45.4 with `apple/project.yml` as the source of truth. Modified the YAML, regenerated the pbxproj reproducibly. Zero risk of structural corruption from hand-edits.

2. **Weak reference bug in test helpers (no production impact).** First iteration of `test_refresh_calls_reload_after_completion` failed because `let (chart, _) = makeSubject(...)` discarded the `MainWindowViewModel` strong reference. `ChartViewModel` holds `mainViewModel` as `weak`, so the second `reload(for:)` inside `refresh()` short-circuited at `if let range = mainViewModel?.dateRange`. **Fix:** retain `main` explicitly in all refresh-touching tests (`let (chart, main) = ...; _ = main`). Documented in test comments so future authors avoid the same trap. Initial reload still works without the explicit retain because the Combine `.sink` closure captures `range` by value.

3. **Additional `initHistoryFn` seam vs AC-8 spec.** The story listed 3 seams (refresh/query/budget). When stubbing `queryFn`, the lazy `ffiInitHistory(dbPath: nil)` call inside `reload(for:)` still tried to hit real SQLite. Added a 4th seam (`initHistoryFn`) defaulting to the real FFI call — production behavior is byte-identical. Documented in the AC matrix as "PASS+1".

4. **Test scheduler timing (`refresh()` → `reload(for:)`).** `reload(for:)` is fire-and-forget — it stores a Task in `inFlightTask` and returns. A few `Task.yield()` calls don't always drain the MainActor queue after `refresh()` returns because the new task gets queued behind the test's continuation. Replaced with `pollUntil(timeout:)` (5 ms real-clock sleeps interleaved with assertions). Empirically reliable; suite still runs in < 0.5 s wall-clock.

5. **AC-15 SettingsViewModel coverage (30.40% < 70%).** The uncovered code is dominated by the Keychain save/load functions (`saveKey`, `loadKeysFromKeychain`, `readKey`), which call FFI directly without a DI seam. Wave 5.5.3 explicitly scopes the seam to OAuth probes (AC-6). Adding a `keychainSaveProvider` / `keychainLoadProvider` is straightforward work for Story 5.5.4 — out of scope here per anti-scope `Add tests pra outras ViewModels ...`. AC-15 is "informacional" per story, so this PARTIAL is documented, not blocking.
