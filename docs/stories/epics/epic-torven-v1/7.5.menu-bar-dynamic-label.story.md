**Story ID:** 7.5.menu-bar-dynamic-label
**Status:** Draft — **DEFERRED** (aguarda Apple Developer Program $99/ano, decisão Lorenzo 2026-06-07)
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 7 — Polish + Release (após Wave 5.5)

---

## Story (User Story)

**As a** usuário do Torven com budget configurado e refresh frequente,
**I want** o item da menu bar mostrar dinamicamente o estado atual (símbolo padrão / valor numérico do spend / cor de alerta quando ultrapasso o budget) — funcionando corretamente em setups multi-monitor com `Displays have separate Spaces` on/off,
**so that** eu veja o status do meu gasto AI a qualquer momento sem precisar abrir popover/main window — ganho o "ambient awareness" que é o ponto inteiro do app.

---

## Contexto e Motivação

`MenuBarLabel.swift` (Story 2.2) já é skeleton configurável — `let symbol: String` por design pra essa story poder evoluir sem mexer em `TorvenApp.swift`. ADR-1 §7 documenta AR-8 (NSStatusItem positioning bugs multi-monitor) como spike de Wave 7.

**Duas partes desta story:**

### Part A — AR-8 Spike (multi-monitor NSStatusItem)
SwiftUI's `MenuBarExtra` é abstração nova (macOS 13+) sobre `NSStatusItem` legacy. Reports na comunidade indicam bugs em:
- Multi-monitor com `Displays have separate Spaces = ON`: item pode desaparecer do display secundário
- Notch displays (M1+): label largo é truncado erroneamente
- Mouse-tracking pra popover anchoring desalinha em monitor secundário

**Hipótese inicial:** `MenuBarExtra` em macOS 14+ é estável o suficiente pra v1.0; bugs reported são edge cases que não bloqueiam. **Spike valida e documenta.** Se confirmar bloqueio, fallback é Story 7.5b (`NSStatusItem` programmatic) — fora de scope desta story (escalation path).

### Part B — Dynamic label
Substituir SF Symbol estático por label que reflete:
- **Estado "idle" (sem dados):** SF Symbol `chart.bar.fill` (mantém atual)
- **Estado "OK" (spend < budget):** valor numérico curto, ex: `$3.42`
- **Estado "warning" (spend ≥ 80% budget):** valor + ícone exclamation, ex: `$8.10⚠`
- **Estado "exceeded" (spend > budget):** valor em vermelho, ex: `$12.50` (cor red SF Symbol via Image foreground tint)
- **Estado "refreshing" (Wave 5 ⌘R em progresso):** `ProgressView` mini OU rotating arrow

**Refresh source:** já em main via `ChartViewModel.aggregatedData` + `getBudgetStatus()`. Esta story só consome — não fetcha. Push de updates ao `MenuBarLabel` via `@EnvironmentObject` ou `@StateObject` reuse.

**Decisões cravadas:**
- **WAVE7-D21:** Manter `MenuBarExtra` (SwiftUI). Não migrar pra `NSStatusItem` legacy a menos que AR-8 spike prove blocking.
- **WAVE7-D22:** Label format = `"$X.XX"` (locale-aware: `NumberFormatter.currency`, ZAR/EUR/BRL etc respeitando system locale). Sem custom format string em Settings (Wave 5.5+ opcional).
- **WAVE7-D23:** Aggregate over all configured vendors (sum de todos `getBudgetStatus().currentSpend`). Não per-vendor — UX consistent.
- **WAVE7-D24:** Reduce Motion respeitado — `@Environment(\.accessibilityReduceMotion)`. Se ON: sem rotating arrow durante refresh; usa static "⟳" SF symbol ou simple progress indicator.
- **WAVE7-D25:** Width budget = ~80pt máximo no menu bar (evitar empurrar outros menu items). Se label > 80pt, truncar (`...`) e expandir apenas no hover (Story 5.5+ opcional).

**Referências:**
- AR-8 — `docs/architecture/torven-v1-adr.md` §7
- ADR-1 — Same doc §4 (menu bar skeleton)
- Apple — [MenuBarExtra documentation](https://developer.apple.com/documentation/swiftui/menubarextra) (macOS 13+)

### Part B — Dynamic label

**AC-3:** `MenuBarLabel.swift` aceita novo `enum MenuBarState`:
```swift
enum MenuBarState: Equatable {
    case idle                              // No data yet (cold start)
    case ok(spend: Decimal, currency: String)
    case warning(spend: Decimal, currency: String)
    case exceeded(spend: Decimal, currency: String)
    case refreshing                        // ⌘R in flight
}
```

**AC-4:** `MenuBarLabel.swift` `body` rende baseado no estado:
- `.idle`: `Image(systemName: "chart.bar.fill")` (current behavior preserved)
- `.ok(spend, currency)`: `Text(formattedCurrency(spend, currency)).foregroundStyle(.primary)`
- `.warning(spend, currency)`: `HStack { Text(formatted...).foregroundStyle(.orange); Image(systemName: "exclamationmark.triangle.fill") }`
- `.exceeded(spend, currency)`: `Text(formatted...).foregroundStyle(.red)`
- `.refreshing`:
  - Reduce Motion OFF: `Image(systemName: "arrow.clockwise").rotationEffect(...)` animated
  - Reduce Motion ON: `ProgressView().scaleEffect(0.7)` static or `Image(systemName: "arrow.clockwise")` no rotation

**AC-5:** `MenuBarStateProvider` (ou similar — naming @dev decide) criado para mapear `ChartViewModel.aggregatedData + budgetStatus + isRefreshing` → `MenuBarState`:
```swift
@MainActor
final class MenuBarStateProvider: ObservableObject {
    @Published var state: MenuBarState = .idle
    func update(spend: Decimal?, budgetLimit: Decimal?, currency: String, isRefreshing: Bool)
}
```
- Se `isRefreshing == true` → `.refreshing` (overrides outros estados)
- Se `spend == nil` → `.idle`
- Se `budgetLimit == nil` → `.ok` (sem budget = sem warning/exceeded states)
- Se `spend > budgetLimit` → `.exceeded`
- Se `spend >= 0.8 * budgetLimit` → `.warning`
- Else → `.ok`

**AC-6:** `TorvenApp.swift` instancia `MenuBarStateProvider` como `@StateObject`, propaga pra `MenuBarLabel` substituindo o atual `MenuBarLabel(symbol: MenuBarLabel.defaultSymbol)`. `MenuBarLabel(state: stateProvider.state)`.

**AC-7:** `ChartViewModel` notifica `MenuBarStateProvider` em `reload()` e `refresh()`:
- Após `aggregatedData` populated → call `provider.update(...)`
- `isRefreshing` toggle → call `provider.update(...)` (only `isRefreshing` field changes)
- Cleanup: provider injeção via constructor ou `EnvironmentObject` — @dev decide pattern coerente com Story 4.x

**AC-8:** Locale-aware currency formatting:
```swift
let formatter = NumberFormatter()
formatter.numberStyle = .currency
formatter.currencyCode = currency  // "USD", "EUR", etc
formatter.maximumFractionDigits = 2
formatter.locale = Locale.current
return formatter.string(from: spend as NSDecimalNumber) ?? "\(spend)"
```

**AC-9:** Width constraint — label > 80pt:
- Truncação: `Text(formattedValue).lineLimit(1).truncationMode(.tail)`
- Frame: `.frame(maxWidth: 80)`
- Validar com valor extremo (e.g. `$10000.00 USD = $10,000.00`) — não quebra layout, trunca pra `$10,0…`

**AC-10:** Reduce Motion testado:
- System Settings → Accessibility → Display → Reduce Motion: ON
- Refresh button click → `.refreshing` state — sem rotação animada
- Validar com `@Environment(\.accessibilityReduceMotion)` mock em XCTest OU smoke manual

**AC-11:** Smoke E2E (Lorenzo bench):
- Sem keys configuradas: menu bar = `chart.bar.fill` (idle)
- Configure key OpenRouter + refresh: menu bar = valor real spend formatado
- Set budget `$1` em config: re-refresh → label vira `.exceeded` (red)
- Set budget `$100` em config: re-refresh → label vira `.ok` (default color)
- Click ⌘R: durante refresh → `.refreshing`; após → volta `.ok`

## Dev Notes

### Constraints técnicas

- **`MenuBarExtra(content:label:)` aceita qualquer `View` no `label:`:** `MenuBarLabel(state: …)` plugs in cleanly. ADR §4 já antecipou.
- **State binding latency:** `MenuBarLabel` é re-rendered a cada change em `state`. Performance OK pra < 1Hz updates (refresh é manual ⌘R; spend muda só após refresh). Não há concern pra throttling.
- **System color compliance:** `.foregroundStyle(.red)` respeita dark mode automatically. Não hardcodar hex.
- **Locale `Decimal` formatting:** `NumberFormatter` necessário (não usar string interpolation) pra suportar BR locale (`R$ 21,26`) vs US (`$21.26`).
- **Currency = ?:** vendors retornam currencies diferentes? Anthropic = USD, OpenRouter pode ser USD/cred, Z.AI = USD. **Assumir USD pra v1.0** (`currency = "USD"` hardcoded em provider em ausência de signal real). Hook pra multi-currency = Wave 5.5+ opcional.
