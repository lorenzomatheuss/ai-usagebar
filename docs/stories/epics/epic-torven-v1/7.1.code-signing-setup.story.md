## Story (User Story)

**As a** Torven maintainer preparando o primeiro release distribuível,
**I want** o projeto Xcode configurado com Developer ID Application signing, entitlements explícitas, e um keychain profile `notarytool` pronto pra usar,
**so that** as stories 7.2 (notarization) e 7.4 (release CI) possam consumir uma configuração de signing estável e auditável sem precisar duvidar de identidade, entitlements ou credenciais.

---

## Contexto e Motivação

`apple/Torven.xcodeproj/project.pbxproj` já tem `CODE_SIGN_STYLE = Automatic` e `DEVELOPMENT_TEAM = "${DEVELOPMENT_TEAM}"` (placeholder por variável de ambiente). Mas **nada disso está cravado pra distribuição**: não existe `.entitlements`, não existe Developer ID Application cert instalado no keychain de CI, e não existe `notarytool` profile.

Esta story é a **fundação** de toda a Wave 7: signing instável quebra notarization (7.2), e notarization quebrada quebra Sparkle (7.3) — porque atualizações que falham notarization são rejeitadas silenciosamente pelo Gatekeeper.

**Decisões cravadas (a serem aplicadas):**
- **WAVE7-D1:** Signing style = Automatic com `DEVELOPMENT_TEAM` resolvido via `.xcconfig` local (gitignored) + GitHub secret no CI. Não cravar Team ID em `pbxproj` pra evitar fork friction.
- **WAVE7-D2:** Bundle ID = `com.torven.Torven` (já cravado no pbxproj — mantido).
- **WAVE7-D3:** Entitlements mínimas — Hardened Runtime ON + `com.apple.security.cs.allow-jit` OFF + `com.apple.security.network.client` ON (Rust fetch ⇒ HTTPS). Sem App Sandbox (menu-bar app com Keychain access cross-app — sandbox quebra `~/.claude/.credentials.json` / `~/.codex/auth.json` reads do AR-2 OAuth probe).
- **WAVE7-D4:** notarytool credenciais via App-Specific Password armazenadas em keychain profile chamado `torven-notarytool` (local) / GitHub secrets `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_SPECIFIC_PASSWORD` (CI).

**Referências externas:**
- Apple — [Customizing the notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)
- Apple — [Hardened Runtime entitlements](https://developer.apple.com/documentation/security/hardened-runtime)

**Pré-requisito humano (Lorenzo):**
- Apple Developer account ativa (Lorenzo já tem? Confirmar pré-kickoff @dev)
- Developer ID Application cert emitido e instalado em `~/Library/Keychains/login.keychain-db`
- App-Specific Password gerado em https://appleid.apple.com

## Acceptance Criteria

**AC-1:** Arquivo `apple/Torven/Torven.entitlements` criado com:
```xml
<key>com.apple.security.network.client</key><true/>
<key>com.apple.security.cs.allow-jit</key><false/>
<key>com.apple.security.cs.allow-unsigned-executable-memory</key><false/>
<key>com.apple.security.cs.disable-library-validation</key><false/>
```
Sem `com.apple.security.app-sandbox` (justificativa em WAVE7-D3).

**AC-2:** `apple/Torven.xcodeproj/project.pbxproj` referencia `Torven.entitlements` via `CODE_SIGN_ENTITLEMENTS = Torven/Torven.entitlements;` em Debug e Release configs.

**AC-3:** `apple/Torven.xcodeproj/project.pbxproj` mantém `CODE_SIGN_STYLE = Automatic` e `DEVELOPMENT_TEAM = "${DEVELOPMENT_TEAM}"`. **NÃO cravar Team ID literal** — preserva o pattern de variável.

**AC-4:** Arquivo `apple/Local.xcconfig.example` criado com template:
```
DEVELOPMENT_TEAM = XXXXXXXXXX
CODE_SIGN_IDENTITY = Developer ID Application: Your Name (XXXXXXXXXX)
```
`apple/Local.xcconfig` adicionado a `.gitignore` (raiz e/ou `apple/.gitignore`).

**AC-5:** Configuração do projeto Xcode aponta para `Local.xcconfig` como base config em Debug E Release (via `xcconfig` property no `pbxproj` ou Project → Info → Configurations).

**AC-6:** Build local com `make app` (ou comando equivalente documentado — `xcodebuild -project apple/Torven.xcodeproj -scheme Torven -configuration Release -archivePath build/Torven.xcarchive archive`) produz `.xcarchive` assinada com Developer ID Application — verificado com `codesign -dv --verbose=4 build/Torven.xcarchive/Products/Applications/Torven.app` retornando:
- `Authority=Developer ID Application: ...`
- `TeamIdentifier=<10-char Apple Team ID>`
- `Sealed Resources version=2`
- Sem `unsealed contents present`

**AC-7:** Hardened Runtime ativado — `codesign -dv ... 2>&1 | grep flags` retorna `flags=0x10000(runtime)`.

**AC-8:** `notarytool` keychain profile criado:
```bash
xcrun notarytool store-credentials torven-notarytool \
  --apple-id "$APPLE_ID" \
  --team-id "$APPLE_TEAM_ID" \
  --password "$APPLE_APP_SPECIFIC_PASSWORD"
```
Verificado com `xcrun notarytool history --keychain-profile torven-notarytool` (não precisa ter submissions — só validar credenciais).

**AC-9:** `docs/SIGNING.md` criado documentando:
- Pré-requisitos Apple Developer account + Developer ID cert
- Passo a passo geração App-Specific Password
- Como popular `apple/Local.xcconfig` (a partir do `.example`)
- Como rodar `xcrun notarytool store-credentials` (AC-8)
- Lista de secrets de CI necessários pra 7.2/7.4: `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_DEVELOPER_ID_APPLICATION_CERT_BASE64`, `APPLE_DEVELOPER_ID_APPLICATION_CERT_PASSWORD`

**AC-10:** Smoke test de import: `xcrun notarytool submit build/Torven.xcarchive/Products/Applications/Torven.app.zip --keychain-profile torven-notarytool --wait` retorna `status: Accepted` em runtime real (não-ignored test — só na bench session de @dev/Lorenzo).

### Constraints técnicas

- **Não pode adicionar App Sandbox:** menu-bar app precisa ler `~/.claude/.credentials.json` (Anthropic OAuth — AR-2) e `~/.codex/auth.json` (OpenAI OAuth — WAVE5-D7). Sandbox bloqueia esses paths cross-app. Justificativa cravada em WAVE7-D3.
- **Hardened Runtime obrigatório pra notarization:** sem `flags=0x10000(runtime)`, Apple rejeita submission com error `"The signature does not include a secure timestamp"` ou `"Hardened Runtime is not enabled"`.
- **Não habilitar `cs.allow-jit`:** Torven não usa JIT, manter `false` reduz attack surface e satisfaz Apple's strict review.
- **Embedded frameworks:** `TorvenCore.xcframework` (Rust → UniFFI) **deve ser re-assinado** com Developer ID Application durante archive. Xcode normalmente faz isso automaticamente com Automatic signing, mas validar em AC-6 com `codesign -dv` em cada framework binary dentro do `.app`.
