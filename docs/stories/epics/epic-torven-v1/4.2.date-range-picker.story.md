# Story 4.2 — Date range picker (7d/30d/Custom) bound to HistoryQuery FFI

**Story ID:** 4.2.date-range-picker
**Status:** InReview
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 4 — Main Window + Swift Charts
**Estimated Effort:** S (~0.5 dia — novo componente SwiftUI + ViewModel + binding FFI)

---

## Story (User Story)

Como usuário do Torven na janela de histórico, eu quero selecionar o período de visualização entre 7 dias, 30 dias, ou um range customizado com datas de início e fim, para que os gráficos mostrem exatamente o intervalo que me interessa — sem ser forçado a ver sempre um período fixo.

---

## Contexto e Motivação

A Main Window shell criada na Story 4.1 exibe um placeholder. Esta story introduz o primeiro elemento de UX real: o seletor de período, que controla o `HistoryQuery` passado ao Rust core e portanto governa quais dados todos os gráficos (Stories 4.3-4.6) exibem.

**Decisão WAVE4-D3 (cravada):** 7d / 30d / Custom range picker. `DatePicker .compact` é built-in SwiftUI — sem dependency adicional. Default: 7d ao abrir.

**Por que esta story vem antes dos gráficos (4.3-4.6):**
O `MainWindowViewModel` introduzido aqui publica `@Published var dateRange: DateRange` que os `ChartViewModel`s (4.3+) vão observar. Criar o ViewModel agora define a interface de dados que as stories de chart vão consumir — evita retrabalho de refactor posterior.

**Integração com FFI (delegada para 4.3):**
O `MainWindowViewModel` introduzido nesta story é **state-holder puro** — publica `dateRange` (com `sinceTs`/`untilTs: Int64`) mas NÃO faz FFI calls. A FFI call aggregada (`ffi_query_aggregated` da Story 4.0.5) é responsabilidade do `ChartViewModel` em 4.3, que observa `mainViewModel.$dateRange` via Combine. Esta separação evita que 4.2 dependa de 4.0.5 e mantém o ViewModel de range testável isoladamente.

**Referências ADR:**
- `docs/architecture/torven-v1-adr.md` ADR-4 — custom type mapping: "usar Unix timestamps i64 em FFI surface, converter em Rust e Swift sides"
- `docs/architecture/torven-v1-adr.md` ADR-5 — SQLite via rusqlite; FFI agregada introduzida em Story 4.0.5 (`ffi_query_aggregated`)

## Acceptance Criteria

**AC-1:** `apple/Torven/MainWindow/DateRangePicker.swift` criado com:
- Enum `DateRangeMode: String, CaseIterable, Identifiable` com cases `.days7`, `.days30`, `.custom`
- Struct `DateRange` com `startDate: Date`, `endDate: Date`, propriedade computada `sinceTs: Int64` e `untilTs: Int64` (Unix timestamps para FFI)
- View `DateRangePicker` que exibe `Picker("Period", selection: $mode)` com `.segmented` style para os 3 modos
- Quando `mode == .custom`, exibe dois `DatePicker` com `.compact` label style (`start:` e `end:`)

**AC-2:** Validação do modo Custom:
- Se `endDate < startDate`, botão "Apply" fica desabilitado (`.disabled(endDate < startDate)`)
- Label de erro sutil visível (`Text("End date must be after start date").font(.caption).foregroundColor(.red)`) quando inválido
- Aplicar range apenas após "Apply" — não recarregar live enquanto user edita datas

**AC-3:** `apple/Torven/MainWindow/MainWindowViewModel.swift` criado com:
- Classe `MainWindowViewModel: ObservableObject`
- `@Published var dateRange: DateRange` iniciando com últimos 7 dias (`startDate = Calendar.current.date(byAdding: .day, value: -7, to: Date())!`)
- Método `applyRange(_ range: DateRange)` que atualiza `dateRange` (observadores como `ChartViewModel` em 4.3 reagem via Combine `$dateRange.sink` ou `onReceive`)
- **NÃO faz FFI call** nesta story — `MainWindowViewModel` é state-holder puro. FFI aggregada (`ffi_query_aggregated`) entra no `ChartViewModel` da Story 4.3

**AC-4:** `apple/Torven/MainWindow/MainWindowView.swift` atualizado:
- Injeta `@StateObject var viewModel = MainWindowViewModel()`
- Inclui `DateRangePicker(dateRange: $viewModel.dateRange)` no top bar da janela
- Placeholder `Text("History — Wave 4")` substituído por layout com top bar + área de conteúdo (ainda vazia para charts)

**AC-5:** Default ao abrir: modo 7d ativo, `dateRange` cobre os últimos 7 dias completos (00:00 do dia D-7 até 23:59 do dia D).

**AC-6:** Computed properties `DateRange.sinceTs` e `DateRange.untilTs` retornam Unix timestamps i64 prontos para passar à FFI (`Int64(date.timeIntervalSince1970 * 1000)`). Garantir que para o mesmo `DateRange`, chamadas repetidas a `sinceTs`/`untilTs` são idempotentes (Date determinístico). AC-2 já previne `since > until` no UI; a FFI call em si fica para 4.3.

**AC-7:** Teste SwiftUI snapshot dos 3 modos:
- Estado 7d (default): Picker segmented com "7d" selecionado, sem DatePicker visível
- Estado 30d: "30d" selecionado, sem DatePicker visível
- Estado Custom válido: "Custom" selecionado, 2 DatePickers visíveis, botão "Apply" habilitado
- (opcional) Estado Custom inválido: 2 DatePickers, botão "Apply" desabilitado, mensagem de erro

### Design decisions / deviations
- **`@StateObject` over `@ObservedObject`:** MainWindowView is the singular owner of `MainWindowViewModel` (Risk row #4). `@StateObject` ensures the VM persists across SwiftUI re-renders of the parent NSHostingView. Chart sub-views in 4.3+ will receive the VM via `.environmentObject` or property injection.
- **`onChange` deprecation shim:** macOS 14 deprecated the single-arg `onChange(of:perform:)` in favor of the two-arg closure form (macOS 14+ only). Since our deployment target is macOS 13.0, the older API is required. Added a small private `View.onValueChange(of:perform:)` extension that picks the macOS 14+ form when `#available` and falls back otherwise — keeps the warning out of the build and makes future deployment-target bumps a one-extension delete.
- **Endpoint convention `[start-of-day, end-of-day]`:** `DateRange.last7Days()` returns `00:00 of D-7` → `23:59:59 of D` per AC-5. End-of-day computed via `Calendar` arithmetic (`+1 day -1 second from startOfDay`) — covers the full calendar day inclusively, no fence-post bugs.
- **Timestamps in milliseconds (i64):** matches the `since_ts: i64` parameter signature in Story 4.0.5's `ffi_query_aggregated` (ms epoch). `Int64(date.timeIntervalSince1970 * 1000)` is idempotent for a given `Date`, satisfying AC-6.
- **`MainWindowViewModel.applyRange()` retained per AC-3** even though the picker writes directly via `$dateRange` binding — provides a clear extension point for future programmatic range changes (e.g., chart click-to-zoom in Story 4.4) without forcing those callers to know about the underlying `@Published` machinery.
