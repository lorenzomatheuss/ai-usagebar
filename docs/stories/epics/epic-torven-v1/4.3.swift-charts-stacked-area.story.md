# Story 4.3 — Swift Charts foundation + Stacked area cost chart

**Story ID:** 4.3.swift-charts-stacked-area
**Status:** Ready
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 4 — Main Window + Swift Charts
**Estimated Effort:** M (~1 dia — aggregation layer Rust→Swift + AreaMark stacked + ChartViewModel + legend + perf)

---

## Story (User Story)

Como usuário do Torven na janela de histórico, eu quero ver um gráfico de área empilhada mostrando o custo em USD por vendor ao longo do tempo, para que eu consiga visualizar de forma imediata quanto estou gastando em cada vendor e como os custos evoluíram no período selecionado.

---

## Contexto e Motivação

Esta story entrega o **chart principal** da Main Window e, mais importante, a **foundation de charts**: `ChartViewModel` + `AggregatedSample` que todas as stories seguintes (4.4, 4.5, 4.6) vão reutilizar ou estender. É o investimento de infraestrutura que desbloqueia as 3 stories de chart restantes da Wave 4.

**Decisão WAVE4-D4 (cravada):** Todos os 4 chart types são entregues nesta wave. Esta story entrega o chart 1/4 (stacked area cost) e a fundação para os demais.

Depende de Story 4.0.5 (FFI ffi_query_aggregated) para consumir TimeBucket[] aggregated data. Sem 4.0.5, esta story está bloqueada.

**Arquitetura do pipeline de dados:**
```
SQLite GROUP BY (Rust) ──FFI──► ChartViewModel.swift ──► AggregatedSample[] ──► Chart { AreaMark }
    ↑                              ↑
ffi_query_aggregated()        observa MainWindowViewModel.$dateRange via Combine
(Story 4.0.5)
```

**Estratégia de buckets (delegada ao Rust):**
A estratégia de bucket é controlada pelo enum `BucketStrategy` (UDL, da Story 4.0.5):
- `.auto` (default em Wave 4) → range ≤ 7d → Hourly; ≤ 30d → Daily; > 30d → Weekly (limits AC-4 da 4.0.5)
- Hard cap garantido pela 4.0.5: ~840 buckets × 5 vendors = 4200 AreaMark no pior caso (7d hourly)

**Performance NFR:**
ADR §6 nota: "Performance teto se v1.5 trouxer históricos longos (~10k+ pontos). Mitigação: downsample server-side Rust." Para Wave 4, target: render < 100ms para 30d × 5 vendors (30 buckets × 5 = 150 marks). Worst-case 7d × 5 vendors = 840 marks aceitável.

**Referências ADR:**
- `docs/architecture/torven-v1-adr.md` ADR-6 — Swift Charts, API declarativa, `AreaMark`, `.stacked`, legend
- `docs/architecture/torven-v1-adr.md` ADR-5 — SQLite + history layer
- Story 4.0.5 — `ffi_query_aggregated`, `TimeBucket`, `BucketStrategy` UDL surface (BLOCKER)
- `docs/architecture/torven-v1-adr.md` ADR-4 — async FFI + `Task { }` pattern

## Acceptance Criteria

**AC-1:** `apple/Torven/MainWindow/Charts/AggregatedSample.swift` criado com:
- Struct `AggregatedSample: Identifiable` com campos: `id: UUID`, `timestamp: Date` (derivado de `TimeBucket.bucketStartTs` em ms via `Date(timeIntervalSince1970: Double(bucketStartTs) / 1000)`), `vendor: String`, `costUsd: Double` (de `TimeBucket.costSumUsd`), `requestCount: Int` (de `TimeBucket.requestCount`, cast `Int(...)`)
- Struct `ChartData` com `samples: [AggregatedSample]`, propriedade `vendors: [String]` (lista única ordenada de vendors), `isEmpty: Bool`
- Função estática `AggregatedSample.fromFFI(_ buckets: [TimeBucket]) -> ChartData` que traduz o array de `TimeBucket` (output de `ffi_query_aggregated` — Story 4.0.5) em `ChartData`. Preserva ordem ASC já garantida pela 4.0.5 AC-5

**AC-2:** `apple/Torven/MainWindow/Charts/ChartViewModel.swift` criado com:
- Classe `ChartViewModel: ObservableObject` observando `MainWindowViewModel.$dateRange` via Combine (`.sink` ou `.onReceive`)
- `@Published var chartData: ChartData` atualizado via `Task { }` quando `mainViewModel.dateRange` muda
- Método `reload(for range: DateRange)` que chama `ffi_query_aggregated(vendor: "", accountFilterMode: .all, accountId: nil, sinceTs: range.sinceTs, untilTs: range.untilTs, bucketStrategy: .auto)` via FFI (função UDL exposta pela Story 4.0.5), e mapeia o `[TimeBucket]` resultante para `ChartData` via `AggregatedSample.fromFFI(_:)`
- **Não redeclarar `BucketStrategy`** em Swift — usar o enum gerado pelo UniFFI a partir do UDL da 4.0.5 (já disponível em `apple/Torven/Bridge/Generated/torven_core.swift` após `cargo build`)
- Tratamento de erro: `HistoryFfiError` em catch — exibir `Text("Failed to load history: \(err)")` no chart placeholder; não propagar crash

**AC-3:** `apple/Torven/MainWindow/Charts/StackedAreaChart.swift` criado com:
- View `StackedAreaChart: View` recebendo `chartData: ChartData` como parâmetro
- Body:
  ```swift
  Chart {
      ForEach(chartData.samples) { sample in
          AreaMark(
              x: .value("Time", sample.timestamp),
              y: .value("Cost (USD)", sample.costUsd)
          )
          .foregroundStyle(by: .value("Vendor", sample.vendor))
          .interpolationMethod(.catmullRom)
      }
  }
  .chartForegroundStyleScale(vendorColorMapping)
  .chartXAxis { AxisMarks(preset: .aligned) }
  .chartYAxis { AxisMarks(format: .currency(code: "USD")) }
  .chartLegend(position: .bottom, alignment: .center)
  ```
- Propriedade `vendorColorMapping: KeyValuePairs<String, Color>` com as 5 cores de vendor brand: OpenRouter (roxo), Anthropic (laranja), OpenAI (verde-escuro), Z.AI (azul), OpenRouter fallback (cinza)

**AC-4:** Empty state: quando `chartData.isEmpty == true`, exibe `ContentUnavailableView("No Data", systemImage: "chart.xyaxis.line", description: Text("No usage history in the selected range"))` ou equivalente compatible com macOS 13 (`ContentUnavailableView` é macOS 14+; para 13: custom `VStack` com ícone + texto centralizado).

**AC-5:** `MainWindowView.swift` atualizado para incluir `StackedAreaChart` na área de conteúdo:
- `@StateObject var chartViewModel = ChartViewModel(mainViewModel: viewModel)`
- Chart ocupa a área principal da janela com `.frame(maxWidth: .infinity, maxHeight: .infinity)`
- Placeholder `Text("History — Wave 4")` removido

**AC-6:** Hover/tap annotation: ao hover sobre um ponto no chart, exibe `chartProxy`-based annotation mostrando data + vendor + custo:
```swift
.chartOverlay { proxy in
    GeometryReader { geometry in
        Rectangle().fill(.clear).contentShape(Rectangle())
            .onContinuousHover { phase in ... }
    }
}
```
Overlay mostra `VStack { Text(date); Text(vendor); Text("$\(cost, specifier: "%.4f")") }` em `chartBackground` ou `annotation`.

**AC-7:** `accessibilityReduceMotion` respeitado: se true, não usar `.animation(.easeInOut)` nas transições de range/data. Usar `.animation(reduceMotion ? .none : .easeInOut, value: chartData)`.

**AC-8:** NFR-1 performance: render < 100ms para 30d bucket diário (30 buckets × 5 vendors = 150 marks) medido visualmente. Para 7d bucket horário (168 × 5 = 840 marks), render aceitável sem freeze de UI. Documentar no Change Log se `.chartPlotStyle { $0.compositingGroup() }` foi necessário para manter performance.

**AC-9:** Teste Swift (XCTest ou snapshot): `AggregatedSample.fromFFI([TimeBucket])` com input sintético de 3 buckets em 2 vendors retorna `ChartData` com 3 samples e `vendors: ["anthropic", "openrouter"]` (ou ordem definida). Os testes Rust da query agregada já estão cobertos pelos AC-7/AC-8/AC-9/AC-10 da Story 4.0.5 — não duplicar aqui.

**AC-10 (opcional):** `#Preview` em `StackedAreaChart.swift` com mock `ChartData` de 5 vendors × 7 dias, exibindo chart com cores de vendor.

## Risks

| Risco | Severidade | Mitigação |
|---|---|---|
| NFR-1: > 5000 AreaMarks causa jank visível (ex: 365d hourly × 5 vendors = 43800 marks) | High | BucketStrategy.auto limita a buckets razoáveis; para custom range longo, forçar bucket semanal. Documentar limite hard de 2000 marks no ChartViewModel. |
| `TimeBucket` shape (output da 4.0.5) é flat com `vendor` por bucket — Swift precisa agrupar por vendor para o `.foregroundStyle(by:)` do `AreaMark` | Low | Resolvido: `AreaMark(... ).foregroundStyle(by: .value("Vendor", sample.vendor))` faz o stacking automaticamente; SwiftUI cuida do agrupamento. Não precisa pré-agrupar em Swift. |
| Combine vs `onChange` para observar `dateRange`: `onChange` em iOS 17+ / macOS 14+ tem API diferente | Low | Usar `.onReceive(viewModel.$dateRange)` com `Combine` para compatibilidade macOS 13+ |
| `ContentUnavailableView` macOS 14+ only: usar `if #available` com fallback custom | Low | AC-4 já prevê; implementar custom fallback para macOS 13 |
| Cores de vendor brand sem asset catalog: definir como constantes estáticas ou em asset catalog? | Low | Definir em `StackedAreaChart.swift` como `static let vendorColors: [String: Color]` — simples, sem necessidade de asset catalog para Wave 4 |
