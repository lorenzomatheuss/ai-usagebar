# Story 4.5 — Request count chart (segunda métrica: Cost / Requests tab)

**Story ID:** 4.5.request-count-chart
**Status:** Ready
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 4 — Main Window + Swift Charts
**Estimated Effort:** S (~0.5 dia — parametrizar charts existentes por metric enum + Picker Cost/Requests)

---

## Story (User Story)

Como usuário do Torven que quer entender não só o custo mas também o volume de chamadas às APIs, eu quero alternar a visualização dos gráficos entre "Cost (USD)" e "Requests (count)", para que eu consiga identificar se estou fazendo muitas chamadas baratas (token economy) ou poucas chamadas caras, e tomar decisões informadas sobre qual vendor ou modelo usar.

---

## Contexto e Motivação

As Stories 4.3 e 4.4 entregam os charts com a métrica "Cost". Esta story adiciona a segunda dimensão de análise: o número de requests. A arquitetura de 4.3/4.4 já prevê `requestCount: Int` no `AggregatedSample` — o trabalho aqui é parametrizar os charts existentes para renderizar essa métrica alternativa.

Depende de Story 4.0.5 (FFI ffi_query_aggregated) para consumir TimeBucket[] aggregated data. Sem 4.0.5, esta story está bloqueada.

**Decisão WAVE4-D4 (cravada):** Todos os 4 chart types entregues na Wave 4. Este é o chart 3/4 — mas não cria chart novo, parametriza os existentes (StackedAreaChart + PerVendorGrid) para suportar a segunda métrica.

**Abordagem de implementação (mínima regressão):**
Introduzir enum `ChartMetric` com cases `.cost` e `.requests`. Passar esse enum para `StackedAreaChart` e `PerVendorGrid` como parâmetro. Os charts usam `sample.costUsd` quando `.cost` ou `sample.requestCount` quando `.requests`. Mudança cirúrgica, sem reescrever os charts.

**Por que não é uma nova view separada:**
Os charts são estruturalmente idênticos — apenas o valor no eixo Y muda. Parametrizar é mais limpo do que duplicar e cria uma abstração reusável para métricas futuras (tokens, latência, etc.) em Wave 5.

**Referências ADR:**
- `docs/architecture/torven-v1-adr.md` ADR-5 — `UsageSnapshot` contém `tokens_used: i64?` e implicitamente request count (1 snapshot = 1 request normalmente)
- Story 4.3 — `AggregatedSample.requestCount`, `StackedAreaChart` (a ser parametrizado)
- Story 4.4 — `PerVendorGrid`, `MiniVendorChart` (a serem parametrizados)

## Acceptance Criteria

**AC-1:** Enum `ChartMetric` definido (em `AggregatedSample.swift` ou arquivo próprio):
```swift
enum ChartMetric: String, CaseIterable, Identifiable {
    case cost = "Cost"
    case requests = "Requests"

    var id: String { rawValue }

    var yAxisLabel: String {
        switch self {
        case .cost: return "Cost (USD)"
        case .requests: return "Requests"
        }
    }
}
```

**AC-2:** `StackedAreaChart.swift` parametrizado para aceitar `metric: ChartMetric`:
- Assinatura: `StackedAreaChart(chartData: ChartData, metric: ChartMetric)`
- `AreaMark(y: .value(metric.yAxisLabel, metricValue(sample, metric)))` onde `metricValue` retorna `sample.costUsd` ou `Double(sample.requestCount)` conforme o enum
- Y-axis format adapta: `.currency(code: "USD")` para `.cost`, `Decimal.FormatStyle()` (número inteiro) para `.requests`
- Todos os snapshot tests de `StackedAreaChart` com métrica `.cost` continuam passando (sem regressão visual)

**AC-3:** `MiniVendorChart.swift` parametrizado para aceitar `metric: ChartMetric`:
- Assinatura: `MiniVendorChart(vendorId: String, samples: [AggregatedSample], metric: ChartMetric, onTap: ...)`
- Total header adapta: `"$\(totalCost, specifier: "%.2f") total"` vs `"\(totalRequests) requests"`
- LineMark Y adapta conforme metric

**AC-4:** `MainWindowView.swift` atualizado com Picker "Cost / Requests":
- `Picker("Metric", selection: $chartMetric) { ... }` com `.segmented` style no top bar (ao lado do Aggregate/Per-vendor picker da 4.4)
- `@State var chartMetric: ChartMetric = .cost`
- `chartMetric` passado para `StackedAreaChart` e `PerVendorGrid` como parâmetro
- Default: `.cost` ao abrir a janela

**AC-5:** Sem regressão — ao alternar Cost → Requests → Cost, o range selecionado e o modo Aggregate/Per-vendor permanecem inalterados. Os states são independentes.

**AC-6:** `ChartViewModel` expõe `samplesByVendor` com `requestCount` já populado (não apenas costUsd). Verificar que `AggregatedSample.fromFFI` mapeia o campo `requestCount` corretamente a partir de `TimeBucket.request_count: u32` (exposto pela Story 4.0.5) — map direto `Int(bucket.requestCount)`.

**AC-7:** Teste: trocar métrica Cost → Requests → Cost mantém o range de datas selecionado e o modo de visualização (teste de regressão de state).

## Risks

| Risco | Severidade | Mitigação |
|---|---|---|
| `TimeBucket.request_count: u32` é fonte primária (exposed by Story 4.0.5 AC-1) — 1 row em `history` = 1 request | Low | Map direto `Int(bucket.requestCount)` em `AggregatedSample.requestCount`. Limitação conhecida: vendors que fazem batching server-side podem subreportar (ex: OpenAI batch API conta 1 row para N prompts). Documentar no Change Log; precisão exata fica para Wave 5 se houver demanda. |
| Y-axis format para integers (requests): `Decimal.FormatStyle()` vs `Int.FormatStyle()` em macOS 13 | Low | `Chart` aceita `Double` no `AreaMark`/`LineMark`; Y-axis format: usar `.chartYAxisLabel` com string simples se formatação automática não funcionar corretamente |
| Top bar com 3 pickers (DateRange + Aggregate/Per-vendor + Cost/Requests) pode ficar apertado na janela 900pt | Low | Usar `HStack(spacing: 12)` com `.fixedSize()` nos pickers; se necessário, mover um picker para toolbar ou segunda linha — documentar decisão no Change Log |
| Regressão visual em StackedAreaChart: adicionar parâmetro `metric` quebra callers existentes em 4.3 | Low | Default do parâmetro `metric: ChartMetric = .cost` evita breaking change; todos os callers existentes continuam compilando |

### Key decisions

1. **Enum location** — `ChartMetric` added to `AggregatedSample.swift` (not a separate file). Trivial 2-case enum, co-located with other chart-domain types; single import per caller. Promotion to its own file deferred to Wave 5 when tokens/latency metrics arrive.
2. **Default `.cost`** — All 3 chart structs (`StackedAreaChart`, `MiniVendorChart`, `PerVendorGrid`) default `metric: ChartMetric = .cost`. Story 4.3/4.4 callers (and previews) compile unchanged.
3. **Y-axis format** — `IntegerFormatStyle<Int>()` for `.requests` (over `Decimal.FormatStyle`). macOS-13-safe, no decimals, no foundation-type sprawl.
4. **MiniVendorChart Y-axis** — Stayed `.automatic` regardless of metric. At 5-up grid scale ticks are visual scale cues; header already names the unit; formatting them differently would be noise.
5. **Top-bar density (Risk #3)** — Picked option (a): reduce widths. ViewMode 220→180pt; ChartMetric 160pt. Total at 900pt: ~656pt with ~244pt headroom for Custom date-range expansion. Single-line layout preserved.
6. **State independence (AC-5)** — `chartMetric`, `viewMode` (both `@State` in `ChartContent`), and `dateRange` (`@Published` on `MainWindowViewModel`) are three independent property sources. Toggling any one cannot reset the others — verified by code inspection (no shared backing store, no cross-binding).
7. **`requestCount` FFI source** — Confirmed at `AggregatedSample.swift:150`: `requestCount: Int(bucket.requestCount)`. `TimeBucket.request_count: u32` (Story 4.0.5 AC-1, UDL-generated) → `Int` Swift. NOT MODIFIED in this story — only verification per T6.
