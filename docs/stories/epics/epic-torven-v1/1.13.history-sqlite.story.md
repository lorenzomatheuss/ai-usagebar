# Story 1.13 — History SQLite layer no torven-core + FFI helpers

**Story ID:** 1.13.history-sqlite
**Status:** In Review
**Epic:** Torven v1.0 — Pivot macOS native
**Estimated Effort:** M (1 dia)

---

## Story (User Story)

Como desenvolvedor do Torven, eu quero um módulo `history` em `torven-core` com schema SQLite versionado (rusqlite + rusqlite_migration), funções para gravar snapshots de uso e consultá-los por vendor/account/período, e helpers FFI expostos via UDL, para que o histórico de uso seja persistido desde o primeiro refresh e o AI Insights (Story 1.15) tenha dados para analisar.

---

## Contexto e Motivação

FR-12 do PRD especifica persistência local de snapshots em SQLite (`~/Library/Application Support/Torven/history.db`). O AI Insights (FR-7 e Story 1.15) precisa de ao menos 7 dias de histórico para gerar análises — logo este módulo deve ser construído antes.

Esta story entrega o SQLite como storage layer no Rust core, completamente desacoplado de SwiftUI. Swift consome os dados via FFI helpers definidos no UDL.

**ADR-5 é explícito:** Swift NÃO toca SQLite diretamente. Toda query passa pelo Rust core via FFI.

**Referência:** `docs/architecture/torven-v1-adr.md#adr-5` (History storage: SQLite via rusqlite).

## Acceptance Criteria

**AC-1:** `rusqlite = { version = "0.31", features = ["bundled"] }` e `rusqlite_migration = "1.2"` adicionados em `crates/torven-core/Cargo.toml`.

**AC-2:** Schema SQLite inicial em `crates/torven-core/src/history/migrations/001_initial.sql`:
```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version INTEGER PRIMARY KEY,
    applied_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS usage_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    vendor TEXT NOT NULL,
    account_id TEXT,
    ts INTEGER NOT NULL,  -- Unix epoch ms
    cost_usd REAL,
    tokens_used INTEGER,
    pct_used REAL,
    metric_kind TEXT NOT NULL,  -- 'percent_window' | 'messages_quota' | 'usd_spent'
    raw_payload_json TEXT
);

CREATE INDEX idx_snapshots_vendor_ts ON usage_snapshots(vendor, ts);
CREATE INDEX idx_snapshots_account_ts ON usage_snapshots(account_id, ts) WHERE account_id IS NOT NULL;

CREATE TABLE IF NOT EXISTS insights_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts INTEGER NOT NULL,
    prompt_version TEXT NOT NULL,
    schema_version TEXT NOT NULL,
    cost_usd REAL NOT NULL,
    latency_ms INTEGER NOT NULL,
    output_json TEXT NOT NULL
);
```

**AC-3:** Migrations rodam automaticamente no startup via `rusqlite_migration::Migrations`. Se migration falhar, retornar `HistoryError::MigrationFailed` com mensagem clara.

**AC-4:** Funções públicas em `history/mod.rs`:
- `pub fn record_snapshot(db: &HistoryDb, snapshot: &UsageSnapshot) -> Result<i64, HistoryError>`
- `pub fn query_snapshots(db: &HistoryDb, vendor: &str, account_id: Option<&str>, since_ts: i64, until_ts: i64) -> Result<Vec<HistorySnapshot>, HistoryError>`
- `pub fn run_retention_janitor(db: &HistoryDb, retention_days: u32) -> Result<u64, HistoryError>` — deleta snapshots mais antigos que N dias

**AC-5:** FFI helpers declarados no UDL:
```udl
dictionary HistorySnapshot {
    i64 id;
    string vendor;
    string? account_id;
    i64 ts;
    f64? cost_usd;
    i64? tokens_used;
    f64? pct_used;
    string metric_kind;
};

namespace torven_core {
    sequence<HistorySnapshot> ffi_query_snapshots(
        string vendor, string? account_id, i64 since_ts, i64 until_ts
    );
    void ffi_record_snapshot(HistorySnapshot snapshot);
    void ffi_run_retention_janitor(u32 retention_days);
};
```

**AC-6:** `HistoryDb` inicializado de `~/Library/Application Support/Torven/history.db` no macOS. Path configurável via `HistoryConfig` (da Story 1.6). Se diretório não existe, criar automaticamente.

**AC-7:** Testes de integração em `crates/torven-core/tests/history_e2e.rs` com banco em `tempfile::tempdir()`:
- `test_record_and_query()`: gravar 3 snapshots, consultar, verificar count e campos
- `test_retention_janitor()`: gravar snapshots com timestamps variados, rodar janitor com 90d, verificar que apenas recentes sobram
- `test_migration_idempotent()`: rodar migration 2x no mesmo DB, sem erro

**AC-8:** `cargo test -p torven-core` passa incluindo os testes de history.

## Dev Notes

### Architecture References

- **ADR-5** (`docs/architecture/torven-v1-adr.md#adr-5`): SQLite via rusqlite. Schema completo (tabelas `accounts`, `usage_snapshots`, `insights_history`, `schema_migrations`). FFI helpers via UDL. Swift NÃO toca SQLite diretamente.
- **ADR-5 Recovery** (`docs/architecture/torven-v1-adr.md#adr-5`): se SQLite corromper, Rust detecta no startup, renomeia para `history.db.corrupt-{ts}`, cria novo arquivo, aplica migrations. Swift recebe `on_storage_recovery(message)` callback.
- **FR-12** (`docs/prd/torven-v1.md#fr-12`): retention default 90 dias configurável. Schema migrations automáticas no startup. Export CSV/JSON (a implementar em Story futura).

### Nota sobre WAL mode

```rust
conn.execute_batch("
    PRAGMA journal_mode=WAL;
    PRAGMA foreign_keys=ON;
    PRAGMA synchronous=NORMAL;
")?;
```

WAL mode permite reads concorrentes com writes — importante porque o scheduler de refresh escreve snapshots enquanto a UI consulta para charts.

### Nota sobre account_id

O `account_id` usado em SQLite deve ser consistente com o gerado na Story 1.6 (Config migration). Convenção: `"{vendor_id}-{account_name}".to_lowercase()`. Para vendors OAuth (Anthropic, OpenAI, Gemini) sem multi-account, `account_id = None`.
