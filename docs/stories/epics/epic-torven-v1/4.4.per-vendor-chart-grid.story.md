# Story 4.4 — Per-vendor line chart grid (5 mini-charts)

**Story ID:** 4.4.per-vendor-chart-grid
**Status:** InReview
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 4 — Main Window + Swift Charts
**Estimated Effort:** M (~1 dia — PerVendorGrid + MiniVendorChart + Picker toggle Aggregate/Per-vendor + filtro vendor)

---

## Story (User Story)

Como usuário do Torven que quer analisar o comportamento de custo de cada vendor individualmente, eu quero trocar a visualização principal para um grid de mini-gráficos — um por vendor — com linha de custo e total do período, para que eu consiga identificar rapidamente qual vendor tem o padrão de uso mais irregular ou qual está consumindo mais orçamento no período.

---

## Contexto e Motivação

A Story 4.3 entrega a visão agregada (todos os vendors empilhados). Esta story entrega a visão complementar: cada vendor em sua própria mini-chart, lado a lado em grid. O usuário alterna entre as duas vistas via Picker no top bar.

Depende de Story 4.0.5 (FFI ffi_query_aggregated) para consumir TimeBucket[] aggregated data. Sem 4.0.5, esta story está bloqueada.

Esta story reusa **completamente** a infraestrutura de 4.3 (`ChartViewModel`, `AggregatedSample`, vendor colors) — o trabalho aqui é a camada de apresentação, não de dados.

**Decisão WAVE4-D4 (cravada):** Os 4 chart types são todos entregues na Wave 4. Este é o chart 2/4.

**Interatividade adicional (click para filtrar):**
Clicar num `MiniVendorChart` filtra a `HistoryQuery` para aquele vendor only — o stacked area chart de 4.3 (visível ao voltar para "Aggregate") também reflete esse filtro. Este padrão é comum em dashboards analíticos.

**Layout adaptativo:**
O grid usa `LazyVGrid` com 2 ou 3 colunas dependendo da largura da janela — 2 colunas abaixo de 800pt, 3 colunas acima. Com 5 vendors: o grid fica 3+2 ou 2+2+1.

**Referências ADR:**
- `docs/architecture/torven-v1-adr.md` ADR-6 — Swift Charts, `LineMark`, legend
- Story 4.3 — `ChartViewModel`, `AggregatedSample`, `BucketStrategy` (reuso direto)

## Acceptance Criteria

**AC-1:** `apple/Torven/MainWindow/Charts/PerVendorGrid.swift` criado com:
- View `PerVendorGrid: View` recebendo `chartData: ChartData` e `onVendorSelected: ((String?) -> Void)?`
- Usa `LazyVGrid(columns: adaptiveColumns, spacing: 16)` com `columns = [GridItem(.adaptive(minimum: 260))]` para layout responsivo
- Itera sobre `chartData.vendors` e renderiza um `MiniVendorChart(vendorId:samples:onTap:)` por vendor

**AC-2:** `apple/Torven/MainWindow/Charts/MiniVendorChart.swift` criado com:
- View `MiniVendorChart: View` recebendo `vendorId: String`, `samples: [AggregatedSample]` filtrados para aquele vendor
- Chart interno: `Chart { ForEach(samples) { LineMark(x: .value("Time", $0.timestamp), y: .value("Cost", $0.costUsd)) } }` com `.foregroundStyle(vendorColor(vendorId))`
- Header: `Text(vendorDisplayName(vendorId)).font(.headline)` + `Text("$\(totalCost, specifier: "%.2f") total").font(.caption).foregroundColor(.secondary)`
- Empty state inline: se `samples.isEmpty`, exibe `Text("No data").font(.caption).foregroundColor(.secondary)` centralizado no frame do chart
- Background: `RoundedRectangle(cornerRadius: 8).fill(.background).shadow(radius: 2)` para visual de card

**AC-3:** `ChartViewModel.swift` estendido (via extension ou método adicional) com:
- Propriedade `samplesByVendor: [String: [AggregatedSample]]` que retorna `chartData.samples` agrupados por vendor
- Propriedade `selectedVendor: String?` (`@Published`) — nil = todos vendors, non-nil = filtro ativo
- Método `selectVendor(_ vendorId: String?)` que atualiza `selectedVendor`; se o vendor selecionado é o mesmo (toggle), reseta para nil

**AC-4:** `MainWindowView.swift` atualizado com Picker toggle Aggregate/Per-vendor:
- `Picker("View", selection: $viewMode) { Text("Aggregate").tag(ViewMode.aggregate); Text("Per-vendor").tag(ViewMode.perVendor) }` com `.pickerStyle(.segmented)` no top bar (ao lado do DateRangePicker)
- Enum `ViewMode: String, CaseIterable { case aggregate, perVendor }`
- Quando `.aggregate`: exibe `StackedAreaChart(chartData: chartViewModel.chartData)`
- Quando `.perVendor`: exibe `PerVendorGrid(chartData: chartViewModel.chartData, onVendorSelected: { chartViewModel.selectVendor($0) })`
- Default: `.aggregate` ao abrir a janela

**AC-5:** Click em `MiniVendorChart` filtra a visualização:
- `MiniVendorChart` tem `.onTapGesture { onTap?(vendorId) }` chamando o callback
- `PerVendorGrid` propaga via `onVendorSelected`
- `ChartViewModel.selectedVendor` é atualizado
- O card do vendor selecionado exibe borda destacada (`RoundedRectangle(...).stroke(vendorColor, lineWidth: 2)`) como indicador visual de filtro ativo
- Se `selectedVendor != nil` e modo é "Aggregate", o stacked area também filtra (mostra só o vendor selecionado)

**AC-6:** Hover annotation em `MiniVendorChart`:
- Similar ao `StackedAreaChart` — hover mostra data + custo num callout
- Pode ser simplificado: apenas `.chartOverlay` básico sem o tooltip completo da 4.3, desde que legível

**AC-7:** `accessibilityReduceMotion` respeitado: transição Aggregate↔Per-vendor sem animação custom se `reduceMotion` ativo.

**AC-8:** NFR-1 performance: 5 mini-charts × 30 buckets diários = 150 LineMark total — render < 150ms. Verificado visualmente no smoke run. Para 7d horário (5 × 168 = 840 LineMark total), performance ainda aceitável.

**AC-9 (opcional):** `#Preview` em `PerVendorGrid.swift` com mock `ChartData` de 5 vendors × 7 dias.

### Design Decisions

| Decision | Rationale |
|---|---|
| **ViewMode picker location:** moved `topBar` into `ChartContent` (sub-view), not in `MainWindowView` | The picker drives chart-area state; co-locating with the chart view models avoids prop-drilling the binding and keeps `MainWindowView` thin. |
| **`vendorColorMapping` promotion to `AggregatedSample.swift`** (not a new file) | Following user guidance — keeps shared chart infra together (color + display name + sample types). New file would be over-engineered for ~30 LOC of shared helpers. Visibility: default `internal` (per-target scope). |
| **`chartVendorDisplayName` as `switch` (not `[String: String]`)** | Compiler will warn when a new vendor id is added to `chartVendorColorMapping` without a matching display-name case — guides future onboarding. |
| **Hover annotation in `MiniVendorChart`: simplified — no RuleMark, no tooltip card** | At 260pt card width, a full hover card overlaps the chart and the value-axis ticks are already legible. Card relies on `.chartXAxis(values: .automatic(desiredCount: 3))` + `.chartYAxis(values: .automatic(desiredCount: 3))` for orientation. |
| **`StackedAreaChart.selectedVendor` default = nil (not refactor callers)** | Risk #3 mitigation. Story 4.3 PR is already merged; non-breaking default preserves source compatibility and reduces blast radius. |
| **Selection-border always drawn with `lineWidth 0`** (not conditional `.overlay`) | Keeps the card's geometry identical on selection toggle — a conditional `.overlay` would shift the inner content by ~1pt as the border appears, causing visible jitter when clicking. |
| **`samplesByVendor` is a computed property** (not stored) | `Dictionary(grouping:by:)` is O(n) on ≤ 840 samples; the alternative is a stored cache + manual invalidation on every `chartData` republish — more code, more bugs. |
| **`PerVendorGrid` wrapped in `ScrollView`** | A narrow window (< ~560pt) collapses to 2 columns; 5 vendors → 3 rows, which can exceed the chart area's height. `ScrollView` is the user-expected escape hatch. |
