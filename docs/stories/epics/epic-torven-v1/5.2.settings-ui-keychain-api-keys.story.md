# Story 5.2 — Settings UI macOS: API key entry + Keychain persistence

**Story ID:** 5.2.settings-ui-keychain-api-keys
**Status:** Ready
**Epic:** Torven v1.0 — Pivot macOS native (`epic-torven-v1`)
**Wave:** 5 — Settings + Real API
**Estimated Effort:** M (~1 dia — SwiftUI Settings scene + 4 vendor forms + ffi_keychain_set_blob wiring + ffi_keychain_get_blob read-back + masking)

---

## Story (User Story)

Como usuário do Torven que quer monitorar gastos reais de API, eu quero uma tela de Settings nativa macOS onde eu possa colar minha API key para cada vendor — e ver a key mascarada após salvar — para que eu não precise editar arquivos TOML manualmente e o Refresh funcione com minhas credenciais reais.

---

## Contexto e Motivação

A Wave 4 entregou o chart de gastos alimentado por dados seedados. O milestone "testar com APIs reais" (Wave 5) requer que o usuário configure suas API keys de forma segura. A Story 5.1 expõe o fetcher via `ffi_refresh_vendor`; esta story provê a UI que persiste as keys no Keychain via os helpers FFI já existentes (`ffi_keychain_set_blob` / `ffi_keychain_get_blob` — Story 1.20 Done).

**Decisão WAVE5-D2 (cravada):** Settings UI = SwiftUI Settings scene (não NSPanel). Motivo: `Settings { ... }` no body do `App` é o idioma moderno macOS 13+, abre via Cmd+, automaticamente, é sandboxable e não exige `NSApp.runModal`. O `@dev` pode override para NSPanel se descobrir limitação concreta em runtime (ex: macOS 13 bug com MenuBarExtra + Settings scene), documentando no Change Log.

**Fluxo Keychain para vendors API-key-based (OpenRouter, Z.AI):**

```
User cola key no SecureField → "Save" → ffi_keychain_set_blob("openrouter", blob_json_bytes)
                                                ↓
                                    MacKeychainStore::set_accounts_blob
                                                ↓
                                    Keychain login.keychain-db
                                                ↓
Settings abre → ffi_keychain_get_blob("openrouter") → blob_json_bytes → decode → exibir masked
```

**Fluxo Anthropic (OAuth, NÃO API key):**

Anthropic usa OAuth via Claude CLI (`~/.claude/.credentials.json`). O campo "Anthropic" em Settings NÃO deve pedir API key — deve exibir o status do OAuth (Conectado / Desconectado) lendo se o arquivo `~/.claude/.credentials.json` existe e contém token válido. Se o arquivo não existir: exibir "Não configurado — instale o Claude CLI e faça login". @dev pode simplificar para uma label estática "Gerenciado pelo Claude CLI" em Wave 5 se implementar o status check for complexo (decisão YOLO documentada no Change Log).

**Keychain blob format** (de Story 1.20, imutável):

```json
{"version": 1, "accounts": [{"account_id": "<slug>-default", "api_key": "<sk-...>"}]}
```

Para vendors single-account (OpenRouter, Z.AI em Wave 5), o `account_id` segue o padrão `config::account_id(vendor, name)` onde `name = "default"` para entrada manual. O @dev deve verificar o padrão exato em `crates/torven-core/src/config.rs` antes de hardcodar.

**Referências ADR:**
- ADR-2 (`docs/architecture/torven-v1-adr.md#adr-2`) — Keychain logic em Rust: Swift usa apenas `ffi_keychain_set_blob` / `ffi_keychain_get_blob`; nunca armazena api_key em memória Swift além do tempo de digitação
- `CLAUDE.md` invariant: "API keys should no longer remain in config.toml" e "Use the Rust Keychain blob helpers"
- `CLAUDE.md` security discipline: nunca `cat` config files que podem conter api_key

## Acceptance Criteria

**AC-1:** `apple/Torven/Settings/SettingsView.swift` criado com uma SwiftUI `Form` organizando 4 seções de vendor:
- Seção "Anthropic" — status OAuth (label informativa, não SecureField) — gerenciado pelo Claude CLI
- Seção "OpenAI" — status OAuth (label informativa, não SecureField) — gerenciado pelo Codex CLI [WAVE5-D7]
- Seção "OpenRouter" — `SecureField("API Key", text: $openrouterKey)` + botão "Salvar"
- Seção "Z.AI" — `SecureField("API Key", text: $zaiKey)` + botão "Salvar"

> **WAVE5-D7 (QA-resolved 2026-06-06):** OpenAI usa OAuth via `~/.codex/auth.json` (mantido pelo Codex CLI), NÃO Keychain API key. O vendor fetcher `vendors::openai::fetch::fetch_snapshot` em Wave 1 toma `creds_path: &Path`, sem branch `api_key`. CLAUDE.md classifica `~/.codex/auth.json` como OAuth credential file (mesma categoria que `~/.claude/.credentials.json`). Story 5.1 implementa o dispatch OpenAI lendo desse OAuth file; Story 5.2 reflete a mesma realidade na UI — status-only, simétrico a Anthropic. Vendors com SecureField API key reduz para 2 (OpenRouter, Z.AI).

**AC-2:** `TorvenApp.swift` atualizado para incluir a Settings scene:

```swift
Settings {
    SettingsView()
}
```

O atalho Cmd+, abre a janela de Settings automaticamente (comportamento padrão macOS com `Settings` scene).

**AC-3:** Ao abrir Settings, cada `SecureField` (apenas OpenRouter e Z.AI após WAVE5-D7) é populado com a key existente (se houver) — mascarada por `SecureField` nativamente. Fluxo:
- `onAppear`: chamar `ffi_keychain_get_blob(vendor)` via `TorvenCoreBridge` para `"openrouter"` e `"zai"`
- Decodificar blob JSON → extrair `api_key` da primeira entrada `accounts[0]`
- Setar binding da `@State var {vendor}Key: String`
- Se `CredentialMissing` (ffi throws): deixar o campo vazio, sem crash
- OpenAI: NÃO chama `ffi_keychain_get_blob` — vide AC-5 que cobre o status OAuth de OpenAI análogo a Anthropic

**AC-4:** Botão "Salvar" por vendor API-key-based (OpenRouter, Z.AI — após WAVE5-D7) realiza:
- Construir blob JSON: `{"version": 1, "accounts": [{"account_id": "{vendor}-default", "api_key": "{key}"}]}`
- Chamar `ffi_keychain_set_blob(vendor, blob_bytes)` via `TorvenCoreBridge`
- Feedback visual imediato:
  - Sucesso: exibir checkmark verde temporário (`.overlay` ou label) que desaparece após 2s via `DispatchQueue.main.asyncAfter`
  - Erro: exibir `Text("Erro ao salvar").foregroundColor(.red)` inline na seção
- Após salvar com sucesso: o `SecureField` mantém o texto (não limpa) — SecureField já mascara
- Anthropic e OpenAI NÃO têm botão "Salvar" — apenas status read-only (vide AC-5)

**AC-5:** Campos Anthropic e OpenAI exibem status OAuth (read-only, não editável):
- **Anthropic:** verificar existência de `~/.claude/.credentials.json` via `FileManager.default.fileExists(atPath:)`
  - Se existe: `Text("Conectado via Claude CLI").foregroundColor(.green)`
  - Se não existe: `Text("Não configurado — instale o Claude CLI").foregroundColor(.secondary)`
- **OpenAI [WAVE5-D7]:** verificar existência de `~/.codex/auth.json` via `FileManager.default.fileExists(atPath:)`
  - Se existe: `Text("Conectado via Codex CLI").foregroundColor(.green)`
  - Se não existe: `Text("Não configurado — instale o Codex CLI").foregroundColor(.secondary)`
- NÃO tentar ler o conteúdo dos arquivos (CLAUDE.md security discipline: nunca `cat` credentials files; usar apenas `FileManager.fileExists`)

**AC-6:** `SettingsView` deve ter `@State` para estados de loading e error por vendor, evitando que o save de um vendor bloqueie a UI enquanto o Keychain write acontece (usar `Task { }` async).

**AC-7:** `xcodebuild` BUILD SUCCEEDED com o novo `SettingsView.swift` e o `Settings { }` scene em `TorvenApp.swift`.

**AC-8 (edge case):** Se o usuário tentar salvar um campo vazio, o botão "Salvar" deve estar desabilitado (`.disabled(key.trimmingCharacters(in: .whitespaces).isEmpty)`). Não deletar keys existentes com campo vazio — apenas ignorar.

**AC-9 (edge case):** Whitespace trim: ao salvar, a key é trimmed de leading/trailing whitespace antes de serializar no blob (`key.trimmingCharacters(in: .whitespaces)`). Usuário que cola key com espaço acidental não vê erro de auth.

## Risks

| Risco | Severidade | Mitigação |
|---|---|---|
| `Settings` scene em `MenuBarExtra` app (macOS 13): existem reports de bugs com `Settings {}` quando o app usa `MenuBarExtra` como entry point (sem `WindowGroup`). Pode requerer workaround via `NSApp.sendAction(Selector("showSettingsWindow:"), ...)`. | Medium | @dev testa em runtime antes de avançar para T5. Se `Settings {}` não funcionar, workaround = abrir `NSPanel` programaticamente como em stories Wave 3 (`MainWindowController`). Decisão documentada no Change Log. |
| `ffi_keychain_set_blob` / `ffi_keychain_get_blob` lançam erros Swift que precisam ser capturados com `try` — interface gerada por UniFFI usa `throws`. Swift `Task { try? }` suprime o error sem logging. | Low | Usar `try` com `catch` explícito no `saveKey` helper; mostrar erro no `@State` de feedback (AC-4). |
| Blob JSON format incompatível com o formato esperado por `MacKeychainStore` em Rust (Story 1.20 AC-3): Swift serializa o blob manualmente; se o shape divergir, `ffi_refresh_vendor` não encontrará a key. | Medium | @dev verifica o shape exato do blob em `crates/torven-core/src/keychain/mod.rs` (type `AccountSecret`) antes de construir o JSON em Swift. O shape é `{"version": 1, "accounts": [{"account_id": "...", "api_key": "..."}]}`. |
| XcodeGen `project.yml` não inclui `Settings/` directory automaticamente: se o project usa globs para source files, o novo diretório pode não ser detectado. | Low | Verificar `project.yml` glob patterns após criar o arquivo; executar `xcodegen generate` antes do build gate. |
